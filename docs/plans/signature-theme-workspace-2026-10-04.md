# 签名创作工作台与全站主题控件

## 用户问题与调整

原页面常用生成 / 图片下载藏在长面板底部，字体、目标数量和作品样式仍使用默认浏览器外观。验证码重复三套模板，编辑器强制一侧暗色、一侧亮色，营销页面缺少主题入口。

签名页将画像选择、示例、生成、PNG、作品文件打开 / 保存集中到顶部。名字输入、字体与写法数量保留可见；亲手签名、名字库管理、签名上传分类折叠。墨量、作品样式、底色和成图清晰度保留在常用设置；色彩、轮廓、排布尺寸、矢量导出按组展开。桌面加宽作品预览；手机按名字 → 预览 → 画面设置排列。折叠手写板不会丢失笔迹，打开时按实际宽度恢复画布。

新增共享 `UiInput`、`UiSelect`、`DisclosurePanel`、`RenderFeedback`、`CaptchaField` 与控件样式。保留原生表单和 details 的键盘语义，基础控件高至少 44px。验证码三处共用一组件，刷新清空旧答案，字符图片保持原貌，外围遵循主题，不对验证码位图做反色。消除多层嵌套 label。作品字迹、图片和导出底色仍由作品参数确定。

每页都可访问主题按钮，选择持久化到已有 `astra-theme`。编辑器各面板改用共享色板，营销页纸色、文字、筛选、输入和边框同步主题。沉浸作品和首页主图保留各自艺术底色，首页受保护源文件及 Studio `.65/.38/.45` 未改。用户认可的 `FxButton` hover 源文件未改。

## 失败与修复

- Vue 模板格式化将原行内多语句点击事件改成换行，Vite 编译拒绝，type-check 未捕捉。改用独立 `toggleComparison` 方法，产品 build 与真实页面验证后再提交。
- 验证码失败提示在手机上盖住主题按钮，自动化尝试点击时又会停留在提示上，延长其显示时间。统一消息在导航下方显示并提供关闭按钮，真实点击主题验证通过。
- 旧合同直接点击现在折叠的矢量按钮。增加按实际 summary 展开的小型辅助函数；作品 / PNG / SVG / JSON / 区域像素断言保持原门槛。原 `.controls` 改为布局容器后无可截图矩形，字体库合同改截实际 `.source-panel`。
- 加宽预览、增加加载提示后，旧恢复合同的固定尺寸故障注入不再可靠。对待显示画布加明确标记，按用途持续注入 context / 空表面故障；失败时仍必须保留原场景、概览和高清显示。
- 完整恢复回归进一步发现，同样尺寸的概览重新打开后出现不同 RGBA hash。仅固定 GPU 后端的专项短测试曾通过，完整失败 / 取消 / 重试仍失败；继续定位到概览源及高质量缩放。最终对导入模板、导入概览及概览显示使用确定的软件后端，普通生成和高清绘制仍保留已验证路径。概览缩放观感较先前 GPU 滤镜略有变化；完整跨浏览器恢复、失败 / 取消 / 重试、原大到适应 RGBA 零差，PNG / SVG / 原大与冻结输出完全相同。未放宽门槛。

## 验证与限制

全站布局矩阵：22 路由 × 1440 / 390px × 明 / 暗，共 88 组无横向溢出，单一导航、焦点、键盘菜单、历史、减少动效和主题持久化通过。此矩阵主要验证结构，不是逐像素审美或所有设备认证。

独立主题 UI 合同在 Edge / Chrome 各 13 场：真实控件尺寸与主题、输入 10 种写法、手写折叠保留和存入第 11 遍、低频默认收起、真实失败登录后的验证码双主题 / 刷新、营销和独立编辑器的主题入口与实际页面颜色变化通过。API 使用明确的确定性测试替身，不证明生产登录服务已验收。

生产 type-check、相关 ESLint、build 与对应结果 / 项目 / 缩放合同按 [验证证据](../validation/2026-10-04/signature-theme-ui/) 归档。构建继续存在已有大块与布局计算动态导入警告。默认排布算法保持冻结输出，新增可选[轮廓方向引导](./signature-direction-2026-10-04.md)。上传视频继续单独验证，整体商业目标仍未完成。
