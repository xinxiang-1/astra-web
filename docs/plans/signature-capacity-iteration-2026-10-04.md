阶段起点 `b2051ba955418ea26af64a137edcede9ce83a11b`。实现 [独立可操作原型](../prototypes/v10-signature-capacity/index.html)、[算法/来源与预先声明](../research/2026-10-04-signature-capacity/README.md)、开发与 UI 验证脚本；生产名字画与首页保护源未修改，PNG 研究下载免费。

## 实施与修复

以真实模板 alpha 容量解释偏淡问题；不规则矩形分区内完整签名等比正向放置，按实测容量选正笔迹或负笔迹墨版，原图只参与计算。负笔迹明确称拼贴，不冒充自然纯手写画像。历史签名使用来源核验后的贝多芬矢量重绘，排除 Hugo 元数据身份矛盾；字体写法准确标为辅助。

初次严格 tsc 发现探针缺少 label、色板元组展开不能满足调用类型，已修正；环境声明路径改用根目录 env.d.ts，并引用已有 Imagetracer shim 和 ESNext.Disposable。没有降低 strict 门槛或添加依赖。

## 验证与决定

[冻结证据](../validation/2026-10-04/signature-capacity/README.md)：36 组开发对照，候选 12/12 数值通过，纯笔迹 0/12、现有镂空 5/12。独立整幅像素占用审计验证分区完整且不重叠；模板完整、正缩放、原生短边至少 8px；同种子确定与不接收原图的重放完全一致。容量饱和每幅 0–725 格，保留原始记录。

Edge / Chrome 各 8 个真实 UI 场景：全 RGBA 对照、1:1 裁片、免费 PNG 文件 hash、≥44px 控件、键盘焦点、390×844 减少动效、无横向溢出和页面异常。不是 Safari 或真手机验收。

严格候选 tsc、相关 ESLint（含两个脚本）、产品 type-check 与 build 通过。原有 stream/JSZip、动态导入及大 chunk 提示仍存在。冻结源码/素材 hash 复核全部相符。

实际查看整幅、原生裁片与手机截图：人脸对比明显提升，但负墨版矩形阶梯仍明显，长名字空间细节较粗。**数值通过，商业审美未通过；不接入生产。** 候选 1024px 完整绘制/同步读回 P95 66.5–115.8ms，不与生产 2K/100 模板计时宣称加速。

## 下一步与边界

最多两轮，这是 R1。R2 在改实现前独立声明，考察分析≤1024、输出 2K/4K 与更大原生笔迹下细节改善，所有基线使用相同输出尺寸。高分辨率不创造源照片细节，也不证明印刷物理可读性。若仍有明显拼贴块面或长名字不可读，按轮次上限停止，保留纯手写与自然排版需求为未完成。旧 native-v2 / ink-pack-v1 不重启，最终 Darwin / Curie 来源不消费。
