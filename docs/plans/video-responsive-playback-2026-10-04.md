# 上传视频播放与页面响应

用户反馈本地上传视频播放时偶尔卡死。本阶段针对编辑器实时预览、高清预解析和全屏：保留六模式采样、原字形、原 RGB 及既有导出，让耗时工作可以让出主线程，并提供等待、慢更新和失败恢复提示。首页三份保护源、Studio .65 / .38 / .45 及用户认可的 FxButton hover 未改。前一阶段签名方向、工作台和双主题见[工作台记录](./signature-theme-workspace-2026-10-04.md)与[方向记录](./signature-direction-2026-10-04.md)。

## 原因与实现

原实时循环按页面帧时钟触发，容易在没有新解码帧时重复转换；采样和逐字绘制都占主线程。仅拆分采样不能解决绘制阻塞。彩色帧频繁改变缓存键，原绘制缓存最多 12000 个临时位图；即使移到 Worker，这些 GPU 分配仍会影响浏览器合成。

- `core.ts` 的字库、明暗直方图和逐行采样共用一个 generator。同步接口遍历到底，新响应式接口约每 8ms 让出执行权，支持取消。字体仍在主线程由真实浏览器生成，单次 Canvas 读写也不能中途暂停；没有把整条管线描述为后台计算。
- 实播优先使用 `requestVideoFrameCallback`，不支持时回退 rAF。重复时间、seeking、数据未就绪、隐藏页、非活动源和忙碌状态不转换。异步转换只运行一份，采样频率依据实际转换与 Worker 绘制耗时调整；不自动降低列数或量化颜色。
- 新绘制 Worker 使用同一 `createCanvasArtRenderer` 工厂。主线程字形 RGBA 在字库变化时发送，Worker 使用 OffscreenCanvas，彩色缓存上限 64；保留 GPU 绘制路径，输出 ImageBitmap。1 像素读回等待当前绘制完成，以实际成本约束调度。共享工厂仅增加可选 surface / cache hooks，原图片、导出及便携输出默认行为保持。
- 每个预览画布最多一份正在绘制的任务和一份最新候选；合并保留真实指针样本，最多 128 个。视频帧与动效共用绘制调度，过期源、设置或隐藏页结果不显示。ImageBitmap 使用后关闭，源替换、卸载和关闭全屏释放 Worker。
- 高清预解析可以 await 响应式采样，继续执行内存预算、取消检查和源时间恢复。视频 waiting / stalled / seeking、绘制超过 150ms 时显示反馈，全屏也有慢更新文字。Worker 构造不可用、运行错误、显示回调错误或 12 秒无响应时销毁并回退兼容 Canvas，页面说明兼容状态。

兼容 Canvas 路径仍会在主线程绘制，在缺少 Worker / OffscreenCanvas 的设备上不能承诺同样性能。保留先解析短片段和用户主动选择清晰度的入口。

## 实际失败与撤回

1. 仅分片采样仍有主线程逐字绘制，因此增加绘制 Worker。无限制的 Worker 彩色缓存仍出现约 917ms 页面帧间隔，改为有限缓存。
2. 全软件 Worker 路径在六模式中出现像素变化，最大通道差 17，撤回。CPU 着色缓存也有偏差（phrase 最大 119）且更慢，撤回相关实现。缓存上限 0 比 64 更慢，恢复 64。最终使用共享 GPU renderer，不以放宽画质门槛换通过。
3. 初版播放测量在视频自然结束后仍采集 rAF，修正为每模式从 0 播放 2.5 秒。暂停稳定性改为等待真实 Worker 空闲，不能以固定 300ms 推断就绪。手机检查先切到效果面板调整清晰度；全屏定位使用实际 `.fs-overlay .ascii-canvas`。
4. 补查发现关闭全屏需要主动释放对应 Worker / renderer，现已修复并由最终 Edge 合同验证两个 Worker 关闭后剩一个。

## 验证

新增 `npm run test:video-responsive`；[精简证据](../validation/2026-10-04/video-responsive/)保留两浏览器报告、最终 Edge 截图及源码 hash。冻结采样与 renderer 取自 `6d140c2eb00fefafcf1be663ed05d30989200dac`。

- Edge 154.0.4258.53、Chrome 154.0.8037.57 均通过 24 组采样（六模式 × 80 / 360 列 × Consolas / 微软雅黑）：同步与分片文字、几何、字形 RGBA、coverage、indices、alpha、colors 与冻结值相同。取消期间计时器仍可运行。
- 两浏览器均通过 18 组绘制（六模式 × static / breathe / rift），Worker 与冻结 renderer RGBA 零差；显示回调抛错、Worker 运行错误两种恢复通过。
- 本地 Canvas + MediaRecorder 真实生成 720p WebM 并上传，六模式各实际播放 2.5 秒；暂停画面稳定、240 列短片段预解析 8 帧、取消 / 恢复、390px 手机无横向溢出及 Worker 不可用的 UI 回退通过。
- 最终 Edge 额外验证全屏 Worker 与关闭后的释放。Chrome 完整合同在最后补充全屏释放及全屏提示前运行；不称 Chrome 已执行该新增断言。
- waiting / 恢复提示通过事件合同；未复现真实网络 stall，不将事件替身当网络稳定性证明。
- 最终相关 ESLint、`npm run type-check`、`npm run build` 均通过。既有大 chunk、layout-compute 动态导入及 stream 外部化警告仍在，未把这些警告称为修复。

当前上传素材、缓存和转换继续在浏览器本地处理。本阶段完成可复核的响应与资源释放改进；下一步性能验收应使用实际用户素材、编码、设备和长时间播放，分别观察解码、采样、Worker 与 GPU，避免重启已撤回的画质降级路径。整体商业目标仍在执行，未部署、未声明真实收款或全项目商业验收。
