# GIF 播放、资源预算与全屏体验

GIF 原来经 createImageBitmap 只取第一帧，根因在素材解码入口。现在使用浏览器 ImageDecoder 逐帧合成、保留原时序，本地编码带透明度的 WebM 再复用视频管线；每帧解码资源关闭，不存整个 GIF 的 RGBA 数组。项目及 `.astra` 始终保存原 GIF 字节，恢复时重新准备本地播放文件，离线 HTML 内嵌派生播放视频。

多帧 GIF 和视频首次渲染即 80 列低清、低消耗预览。循环选项适用于实时播放、缓存播放及离线网页，末帧停止后可以重播。完整画质预览明确等待解析；第一帧预测整个片段预算，文本、实际底层数组、共享字形、可选栅格进入 96 MiB 缓存预算。超限尽早拒绝并恢复源时间；不把这个数字称为整个浏览器堆上限。

支持 12/15/20/24/30/60 fps 与导出长边 720/1280/1920/3840，默认 15 fps / 长边720。导出使用选定列数与逐帧生成，不先缓存全片；编码成品依然占内存。WebCodecs实际时间戳和输出尺寸已验证1920×1080/60fps短片；3840不是所有设备无条件可用承诺。高帧率下完整预览仍受20秒/480帧约束，用户需要缩短片段。

GIF 输入64MiB、最大3000帧、120秒、10亿累计解码像素；派生媒体采用有界 StreamTarget，写入阶段即限制保留编码数据/输出范围64MiB，合并时仍有短时副本，解码器/编码器内部内存不在此预算。旧浏览器缺少ImageDecoder/VideoEncoder时明确报错，不静默显示首帧。

全屏滚动容器按内容尺寸和可视区尺寸居中，画布不被 flex 压缩；工具栏复用同一个主题组件。全屏主题不改变作品墨色、播放或缩放。探索页面原先被 App 当作固定高度编辑器，body滚动关闭；现在仅字符编辑器保留固定布局，探索页采用页面滚动并保留自己页头。

探索页修复推送后再次复核桌面1440×700和手机宽度390×844，滚轮分别滚到436px和809px，即各自页面底部；末尾参数、说明和操作区域可见。截图目视通过，页面没有重复页头。

验证：[真实 GIF / 资源合同](../validation/2026-10-10/gif-resource/browser-r6.json)、[六模式缓存](../validation/2026-10-10/gif-resource/cache-six-modes.json)、[探索页滚动](../validation/2026-10-10/gif-resource/art-lab-scroll.json)。真实用户素材173帧/6.91秒，不提交原始附件；最后一轮进入播放2445ms，之前同机1692ms，不是跨设备性能保证。减少动效下的真实画布变化、循环/停止/重播/暂停、非法替换保留原作品、原字节打包与恢复、离线停止和重播、真实视频默认低清、内存早拒绝、源时间恢复、1920/60fps编码通过。桌面1440×960及窄屏390×844居中误差≤0.008px，主题切换后仍一致；相关截图目视检查完成，未提交用户图像。

type-check、相关ESLint、生产build通过（已有字体/大chunk警告保留）。旧状态合同硬编码IndexedDB v1，且在Worker完成呈现前比较旧画布；修正为v2、固定其经典画质基线、等待对应品质/源比例后，[22项状态合同](../validation/2026-10-10/gif-resource/editor-state.json)通过。浏览器合同初次IPv4访问碰到原服务只监听IPv6，改为localhost；包目录断言修正为现有实际结构，导出后测试主动关闭抽屉。

用户随后指出低清60fps叠加hover/动效仍卡，确认缓存解决采样复用但不解决动态绘制成本。本阶段没有宣称达到高级效果持续60fps，GPU渲染与长期缓存的下一阶段必须用实际呈现延迟和预算验收。认证、验证码、订单、权益均仍由真实后端决定，本地绘制不授予权限。
