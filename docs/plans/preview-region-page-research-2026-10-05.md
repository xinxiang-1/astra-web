# 区域缓存候选的真实编辑器验证

接续[独立区域缓存研究](./preview-region-cache-research-2026-10-05.md)。用户反馈的反复“正在绘制字符画”已在[空闲调度阶段](./preview-feedback-idle-2026-10-05.md)修复；本阶段进一步检查真实操作及缓存候选，不修改生产工厂或页面。生产保留 `92bc304` 的调度、提示与绘制实现。

## 方法与真实范围

新增 `npm run research:preview-region-page`。从冻结工厂重建同一个 R2 候选，再独立打包 Worker；Playwright 只在隔离上下文中将生产页面的绘制 Worker 换成同源候选。真实上传瓷像、点击模式和悬停按钮、鼠标移动、主题和缩放控制，保持 180 列及 `.65/.38`，不注入投递延迟、不伪造请求时间、不降低列数。普通桌面画布实际为 571 × 713，额外操作使用实际缩放和全屏尺寸。

QA 浏览器上下文从 Worker 的第一条实际请求开始保存完整协议，包括首批字形；在生产消费前读取部分完成 bitmap。操作后按原始顺序、原始事件时间重放给原生产 Worker，逐通道比较实际布局的 RGBA。每个 Worker 最多保留 12 幅 bitmap，QA 像素记录总上限 64MiB；候选自身仍是每份静态画面/内容快照 16MiB 上限。记录和读回会增加 QA 开销，端到端耗时是观察值，不是隔离绘制基准或稳定 FPS。

[精简证据](../validation/2026-10-05/preview-region-page/README.md)保存原始报告、失败、实际参数和源码 hash。各报告候选源码 hash 完全一致；生产模块及首页三保护源、Studio 参数、已认可的 FxButton 均未改动。

## 实际发现与修正

1. 初轮中文使用页面默认的单色“我爱你中国”，不能据此称彩色中文已验证。保留初轮报告，脚本增加真实颜色按钮设置及请求 `settings` 记录，再补彩色中文。
2. 彩色中文 R1 已通过真实反馈、精确恢复、静止零请求/零提示及六幅请求重放零差，但“每种聚散手势一定出现局部 patch”的研究断言失败。实际改变面积约 91%，正确触发原有 80% 面积以上的整幅绘制分支。没有改变工厂、强度、轨迹或像素门槛。修正研究合同为记录实际 patch 和广域动态帧；无 patch 时必须证明真正走了广域整幅分支，并明确不代表区域性能收益。原失败保留。
3. 后续同样真实手势有时出现一幅早期局部 patch，随后仍是广域整幅绘制。后台完成时间影响输入合并和原生场推进，不能从一次进入更快推断持续加速。

## 最终验证

Chrome 154.0.8037.57 和 Edge 154.0.4258.53 的真实生产页面流程通过：六模式 180 列聚散有可见反馈、peak > `.005`、60 秒内 PNG 精确恢复，静止 1.5 秒零新请求、普通交互反馈 40ms 采样为零；原色和彩色中文的光晕也保留实际反馈及精确退场。候选实际请求重放加四品质对照，Edge 112 幅、Chrome 111 幅均逐通道零差，总计 223 幅，不含初轮单色中文或假设失败报告。

两浏览器均补齐双主题缩放的必要等待与清除、进行中的尺寸更新取消、四品质真实交互/精确恢复、全屏 2 → 1 Worker、暂停环境仍可 hover、减少动效静态及允许滚动、换图、离页 Worker 归零，以及 390px 布局的 180 列触控。四品质每档各重放 11 幅；柔和双倍栅格、软件面积栅格和环境动效的 region cache bytes 为零，使用原绘制路径。触控每次 1 down / 10 move / 1 up / 0 cancel，是 CDP 输入，不证明实体手机性能。

保留 Chrome 光影模式实际 Canvas 录屏及彩色中文截图，录屏采集请求 30 次/秒不能解释为字符 30fps。Node 语法、研究脚本 ESLint、JSON/hash、文档链接和 diff 检查通过；本阶段没有生产代码变更，未重跑或声称重新通过生产 type-check/build/视频回归。

## 实际操作耗时与决定

以下每行仅各一次真实手势，原模块和候选分开执行；事件时间和实际完成帧数不同。配对像素证明来自候选请求在原 Worker 中的精确重放，并非两次不同手势最终截屏相比较。表中耗时均为 ms，不能计算为稳定加速比。

| 浏览器 / 模式 / 悬停 | 首次可见：原模块 / 候选 | 离开至精确恢复：原模块 / 候选 |
| --- | ---: | ---: |
| Edge / 原色 / 聚散 | 2119 / 1190 | 5754 / 4653 |
| Edge / 彩色中文 / 聚散 | 2611 / 807 | 4937 / 5778 |
| Edge / 原色 / 光晕 | 1760 / 1436 | 3182 / 1798 |
| Edge / 彩色中文 / 光晕 | 1942 / 2103 | 4780 / 4209 |
| Chrome / 原色 / 聚散 | 4216 / 705 | 6725 / 7386 |
| Chrome / 彩色中文 / 聚散 | 4390 / 1500 | 6770 / 5392 |
| Chrome / 原色 / 光晕 | 2392 / 2752 | 5722 / 4218 |
| Chrome / 彩色中文 / 光晕 | 3244 / 3440 | 11076 / 8086 |

候选可更快复用进入初期的静态主画面，但两浏览器都有更慢的聚散恢复，光晕首次反馈也有变慢。实际强手势下，原色/彩色中文常覆盖超过 80% 的画面；一幅早期局部 patch 不足以解决整个连续操作。因此候选继续留在研究，不接入生产，不把减少加载提示称为字符帧已实时。

## 下一步

优先研究广域连续输入的整幅绘制成本及光层成本，继续保持原生场、正向字形、中文顺序、原 RGB/alpha 和既有品质合同。此次发现不支持继续只用小范围轨迹证明通用性能；新加速方案应先覆盖真实宽路径和慢设备，再决定接入。没有重启已停止的签名容量、视频 atlas、软件 tint/LUT 或 tile pool 调参。长视频、真机、真实手写商业画质、原创素材和全站一致性仍继续，整体目标保持 active。
