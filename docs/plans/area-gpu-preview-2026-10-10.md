# 还原品质 GPU 预览、同源帧复用与媒体时钟

## 已交付的范围

编辑器图片/GIF/视频的密度、原色“还原”品质接入 Worker WebGL2 面积滤波。保持原字形、采样、颜色、原生场与电影感几何，GPU 读取同一字形累积面积表并实例化合成，避免 CPU 逐像素遮罩/合成及数千次逐字着色。它不是经典图集双线性采样替代还原，输出允许 GPU 浮点/混合造成的小量像素误差。

源帧以单调 revision 上传，只有源帧对象改变才复制 indices/alpha/colors/text。交互帧复用 Worker 内相同 ArtFrame，保留字形/运动缓存。已解析的视频切换源帧仍更新数据；换素材/字体/尺寸的取消、晚结果丢弃与 bitmap.close 保持。没有转移用户仍需保留的源数组，不把动画列数或品质偷偷降档。

视频原先禁用图片品质；现在可明确选择适用的还原/精细/柔和，视频/GIF 导入分辨率仍默认低清80列，省资源预览及完整画质等待解析仍由用户选择。其它模式/栅格、未支持设备和超预算输出保留完整 Canvas 路径；本阶段不声明中文彩色铺字也达到60fps。

按用户此前要求，编辑器普通预览、全屏、环境视频与新离线 HTML 都传 `glow:false`，关闭隐含字形光层，而保留真实字符形变与明暗。移除光晕入口后，旧引擎仍自动执行第二遍着色/模糊，尤其原色与中文很慢，本次关闭其实际合成。共享工厂缺省与历史独立 HTML 兼容；受保护首页文件和原 Studio 参数未改。PNG仍使用精确CPU静态输出，视频/HTML允许慢渲染，既有免费导出继续免费。

缓存播放时钟不再每帧重置截止时间：用累积相位和0.5ms容差处理16.6/16.7ms抖动，慢帧按真实媒体时间跳过过时源帧，隐藏/暂停冻结时钟；关闭循环必须显示末帧后恰好停止一次。确认使用GPU的交互动效解除原30fps硬上限，依然遵守实际Worker处理预算；这只是取消软件限制，不代表已达到60fps。

## 资源与失败处理

GPU仅在适用还原帧且编辑器关闭光层时懒创建；无WebGL2、创建/绘制异常、context loss、纹理限制及超预算返回完整CPU路径。原生场只推进一次，GPU失败复用同一几何，不重播指针事件。GPU直接转ImageBitmap传主线程，避免先拷回CPU像素；renderMs表示Worker完成时间，不能当作屏幕呈现帧间隔。

新增命令数组复用且最多8MiB；prefix纹理最多4MiB，输出色缓冲估计最多32MiB，另有实例CPU数组/GPUbuffer及原有场/缓存。统计返回这些独立资源，超限在分配前拒绝加速。限额不包含驱动内部副本和浏览器全部堆；仍不宣称浏览器总内存封顶。退场/全屏关闭终止自有Worker，bitmap逐个close；GPUcontext loss后保留CPU回退，不无穷重建context。

## 实验与证据

固定源/字体/时间/轨迹的隔离候选在sandbox开发后晋升；没有付费评审、模型调用或媒体上传。两个候选：原CPU与同几何GPU；不是参数寻优，未用单图作泛化/Pareto审美结论。固定720px、80/180列、Microsoft YaHei、当前Edge154。基线帧驻留r1在认证浏览器同时运行时超过240秒截止，未通过，保留原始失败，不用该轮作性能结论。GPU r1还保留昂贵光层，180列原色没有加速；关闭编辑器光层后r2才显著改善。

同源缓存与GPU Worker隔离12帧测试中，还原80/180列的P95延迟：密度80 123.1ms→32.7ms、密度180 330.8ms→53.5ms，原色80 103.2ms→31ms、原色180 229.7ms→48ms。两个源帧共13次渲染时，完整源数据上传13次→2次。包含真实Worker传输、栅格及主线程drawImage，不能解释为持续呈现FPS。独立同步面积滤波对照四路径中，非透明同帧平均误差不足1/255；透明像素未预乘RGB会在alpha接近0时出现大差值，因此进一步验证预乘RGB与alpha。

正式验证：

- 57项GPU/CPU合同：两个模式、9种hover、透明/不透明、连续时间，实际GPU活动断言；预乘RGB平均误差<1、最大差≤12、alpha差≤3；无WebGL、输出预算和context loss回退通过。第二仓库自有瓷器素材作为独立一致性样本，非训练/留出审美评估。
- 图片已有80项像素/元数据、调度/取消/替换合同通过；旧参数继续严格像素相同。
- 视频已有六模式采样/Worker对照、错误恢复、等待状态、暂停稳定、240列预解析/取消、全屏释放、移动宽度与Worker兼容回退通过。首次测试沿用“超清自动进入解析”的旧UI假设失败；更新为明确选择完整画质/省资源后通过。
- GIF资源合同通过：实际GIF变化、循环/暂停、项目/工作流携带，MP4低清默认与完整品质解析、早期内存拒绝、1920×1080/60fps短片导出、桌面/移动全屏居中，创作没有POST上传。
- 新媒体时钟合同：60Hz抖动不掉半帧、慢帧赶上媒体时间、隐藏后恢复、单次末帧/停止通过。
- type-check、相关ESLint、production build通过；构建仍有已有stream外置、chunk和插件耗时警告，无新增构建失败。

[精简证据](../validation/2026-10-10/area-gpu/manifest.json)保存源哈希、原始耗时与验收记录。原始PNG/浏览器日志留在本地sandbox/output；不提交用户提供的GIF或其截图。

完整编辑器复验入口 `scripts/area-gpu-editor-live.mjs` 要求显式设置 `ASTRA_GIF_FIXTURE` 为自己的本地 GIF 路径；`ASTRA_AREA_EDITOR_URL` 默认生产预览4210，`ASTRA_AREA_EDITOR_OUTPUT` 可指定全新输出目录。提交前移除了脚本中个人临时目录的缺省路径，浏览器交互步骤与已通过r4保持相同；此测试入口调整只检查语法，未重跑产品构建。

## 真实生产页面的限制与下一步

生产4210实际图片/GIF、波浪加拖尾、全屏GPU与主题、低清默认、完整预解析180列选择60fps都通过行为验收。初次脚本找错“流动”按钮名、等待了主画布而非新全屏画布，分别修复测试后通过；失败报告保留。

最新r4实际作品呈现间隔：图片P50约64.6ms/P95约120.6ms，实时GIF39.5/66ms，预解析180列GIF34.6/87.4ms。页面rAF P95约16.8ms，说明页面交互保持响应；作品本身仍会掉帧，不能把页面rAF当成作品60fps。r3/r4之间存在实测波动，解除软件30fps限制没有证明高清呈现达到60fps。

下一步是原生场采样与逐字几何的GPU化，以及classic/中文/其它品质的同源图集路径；以完整编辑器实际呈现帧间隔评估，而不是继续提高下拉框数字。预解析源帧与交互显示保持独立；长素材分页/落盘、LRU、设备预算、10分钟释放后增长及真机持续体验继续按[总体路线](./video-gpu-pipeline-2026-10-10.md)推进。本阶段是已验证的绘制改进，不是最终“高画质全特效无卡顿”的商业验收。
