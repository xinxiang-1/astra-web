# 视频长帧：分段绘制与进度

延续[视频响应阶段](./video-responsive-playback-2026-10-04.md)和[字符聚散接入](./glyph-particles-integration-2026-10-05.md)。当前生产视频已经在Worker绘制，但180列彩色中文仍可能超过12秒，被watchdog当作故障并回退主线程，进一步阻塞页面。

## 实现

- 同一个自包含Canvas工厂提取绘制generator，同步接口直接遍历，后台接口约8ms检查一次时间片。字符、颜色、尺寸、绘制顺序及最终光层不变；不自动降低列数、量化颜色或更换栅格后端。
- Worker在片间读回1像素排空GPU队列，然后让出执行权，只发送递增的已处理字格数；整帧完成后才传送bitmap，显示期间保留上一帧。8ms是检查预算，不是单次Canvas命令或整个GPU调用的硬上限。
- 客户端只接受当前任务、正确容量、有限整数且严格递增的进度，重新开始12秒静默超时。静默、重复、过期或非法进度不能让挂起任务一直存活。进度消费者抛错也销毁Worker；销毁后忽略迟到消息。
- 视频等待提示使用共享RenderFeedback展示当前帧进度，全屏显示百分比。源替换、隐藏和设置过期的进度不更新UI；现有资源释放和一份进行中/一份最新候选的限制保持。
- 提示改为主题浮层，不占预览grid行，也不拦截画布输入。完整R1虽然24组采样、18组冻结绘制和六模式实际播放通过，但暂停后的Worker空闲等待失败；独立真实视频复现预览在844×475与356×200之间跳变，spinner显示/隐藏导致尺寸变化和重复绘制。修复产品布局后再跑完整合同，没有放宽60秒空闲或像素门槛。

## 实际诊断与拒绝方案

单幅Chrome、瓷像、571×713、180×191字格、彩色中文“我爱你中国”，基础drawImage为主要成本。三帧同步GPU耗时21.019 / 8.477 / 7.692秒。CPU目标为22.632 / 8.647 / 8.237秒，RGBA零差但无收益；扩大至64MiB缓存为47.349 / 6.173 / 5.740秒，RGBA零差但仍过慢、首帧和资源更坏。临时bitmap试验首帧54.609秒后主动终止，未取得完整像素报告。不采用上述方案，不扩张生产缓存，也不重开已停止的atlas。

大画面分段Worker两帧21.803 / 18.706秒均完成；此前相同尺寸Worker触发12秒静默超时。最终帧与同步Canvas RGBA零差。期间20ms定时器2046次，P95 31ms、最大171.9ms；页面rAF 2300次，P95 18.5ms、最大109.6ms。这个实验在增加严格进度校验与UI百分比之前运行；不能把页面rAF称为字符输出帧率，也不能将后台仍慢说成渲染提速。

## 验证与剩余范围

精简报告与源码hash放在[证据目录](../validation/2026-10-05/video-render-slices/)。进度及故障注入使用明确的虚拟时钟，不能用其时间证明真实性能。真实大画面、六模式冻结画质、播放、全屏资源、手机与回退分别记录。

Chrome完整R2通过：24组同步/分片采样等于冻结值；18组Worker绘制（六模式×静态/光息/撕裂）RGBA零差；六模式真实720p WebM各播放2.5秒，20ms定时器最大间隔33–47.9ms。页面rAF P95为18.5–35.6ms，轮廓模式仍有374.8ms最大间隔，不能宣称恒定流畅。暂停后Worker空闲与画面hash稳定、240列8帧预解析/取消、全屏两个Worker关闭后剩一个、390px与Worker不可用回退均通过。

独立Chrome反馈合同四场（1440/390px×明/暗）：显示与隐藏等待浮层时预览区域尺寸完全相同、不阻挡输入、无横向溢出、减少动效停止spinner。实际本地H.264输入，buffering使用明确事件替身。最终合同另用自生成VP8 WebM完整通过四场，不依赖预存fixture。QA自动捕获最初生成110字节空WebM，产品正确拒绝；改为手动逐帧捕获并验证编码字节。QA合成素材用CPU Canvas，并未将作品着色切到软件后端。Edge/Chrome各九项watchdog故障合同通过，有进度的虚拟30秒任务完成、静默/重复/非法/过期消息拒绝、消费者异常与销毁释放。

分段改造后的Edge同步聚散24组复验通过，720帧与冻结v9精确一致，自然归位、旧trail、容量及保护源码保持。原作品包/媒体/实际编辑器报告仍是改造前的范围，见各自产生阶段，不称全部重新执行。

最终Edge Worker六模式×透明/不透明12组、888帧与同步Canvas RGBA及活动状态一致，約4.8秒模拟时间自然归位；相同颜色内容的frame克隆维持身份。编辑器/离线HTML超容量bytes=0、touch-action=auto，画布内十次鼠标移动零重绘。未外推到不同解码颜色序列、任意画质或4K。

最终type-check、相关ESLint和产品build通过；已有stream外置、大chunk、layout-compute动态导入警告仍在。

同步图片、PNG/HTML的基础彩色绘制仍有长耗时；图片聚散的生产Chrome完整矩阵尚未通过。软件面积栅格及最后光层并未进一步分片，部分单次GPU操作也无法中断。Worker真正失败时仍保留兼容回退路径；没有证明所有设备/视频/4K都不卡或60fps。下一步需继续定位逐字贴图成本及将昂贵图片预览安全移出主线程，不能以延长测试等待或降低画质宣布通过。
