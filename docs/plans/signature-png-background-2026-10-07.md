# 高清 PNG 后台导出 · 2026-10-07

接续[签名融合风格](./signature-wash-styles-2026-10-07.md)。本阶段解决实际下载时的阻塞，不改变签名、布局、原墨色和免费输出。用户随后提出“下载后放大名字不能模糊、整幅 SVG 后续渲染很卡”；该新要求继续推进分块超清位图，不能以本阶段 8K 或已有 SVG 宣称无限放大清晰已经实现。

## 实施

- PNG 的分块绘制和 `OffscreenCanvas.convertToBlob()` 在独立 Worker 内完成，只回传 Blob，不把整个高清 RGBA 搬回主线程。原 PNG 的尺寸、快照和像素合同保持。
- 排版传输改为分段打包的 Float64 数组，保留坐标、浮点 RGB 与可选布尔缺省。普通预览仍按原能力门槛运行；只有导出开启后台镂空，通过共享 Path2D 几何和原描边算法处理未矢量化模板。
- 清晰显示准备、绘制、编码阶段，支持取消及离页停止；失败自动分段兼容绘制。后台完成/取消释放独立 Worker；兼容输出、缩小模板和分块 Canvas 释放，用户源签名保留。兼容浏览器的 Canvas PNG 编码仍可能暂停页面，未称全浏览器无卡顿。
- 下载使用已生成作品。未应用参数、作品重开、取消和导出失败不丢失原画面；Edge 实际编码失败注入后可重试。公共反馈组件可以显示正确的 PNG 进度标签，两主题继续适配。

## 实际失败与修复

最初模板测试把 `createTextStamp` 的第二参数误写为数字，实际没有测试大模板。纠正 options 并增加 1181×319 合成模板后，软填色出现 2870 个通道差异、最大差 3。椭圆半径、变换、透明度、颜色及 Float64 传输逐项相同；增加后台 readback 没有修复，ImageBitmap 方案又在无填色下产生差异，均拒绝。

最终先按旧 DOM 流程做有界、高质量缩放再传像素，避免把原始 readback 传到 Offscreen 后再缩小。只准备有限模板，不在主线程绘制高清成图。最终保持零差门槛；不把浏览器内部精度机制的推测当已证实结论。

首次 Edge 录屏会话意外关闭，仅完成两类，不算正式通过。Chrome 首次检查错误使用不存在的“返回首页”文字而失败；改为实际首页 logo，在产品源 SHA 未变的前提下续验离页和已下载文件，保留原失败。最终 Edge 无录屏完整运行通过。未将录屏失败或选择器失败归因于产品绘制。

## 验证与性能

原始大文件仅在 ignored `test-results/`，公开精简结果见[验证目录](../validation/2026-10-07/signature-png/summary.json)。生产页面实际生成公开人像与 10 种字体辅助写法；这些是字体辅助样例，不代替真实手写或印刷审美验收。

| 核验 | 范围与结果 |
| --- | --- |
| Edge / Chrome API | 各 64 组纸/夜 × 普通/镂空 × 纯签名/原色/双色/波普 × 染色 × 软填色；含正确尺寸中文、Latin 和 1181px 大模板，已描边/未描边均有。冻结 70de56c 的 layout、trace、vector-ink；旧、新 PNG 全部解码 RGBA 零差。另各 5 类传输/几何、三阶段取消、真实 Worker 构造失败兼容，共各 69 类 |
| 两浏览器生产 UI | 五种 2K 画面及 4K/8K 实际下载。完整旧 PNG 独立重绘并逐条带比较所有解码通道，零差；未应用参数、兼容回退、项目重开也零差。准备/绘制/编码取消、两主题 390px、缩放、离页资源释放通过。Chrome 11 类，Edge 额外编码失败/重试，共 12 类 |
| 高清文件 | 4K 为 3278×4096 / 29070 枚签名；8K 为 6556×8192 / 76913 枚签名 / 73.52 MB。每个 PNG 完整解码，不只读取头部；8K 全部 214827008 个 RGBA 通道与冻结输出一致，另保存概览与原大笔迹裁片 |
| 回归与检查 | 两浏览器响应式冻结对照各 17 类；当前融合配方/项目/Worker/高清区域回归、类型、相关 ESLint、生产 build 结果随精简证据记录。既有大 chunk、JSZip/stream 与 layout-compute import 提示仍保留 |

开发 API 的同输入剖析：旧 4K 总等待 5.62 秒，其中页面 longtask 2.467 秒、最大 rAF 间隔 2.464 秒；后台 4K 总等待 5.59 秒，最大间隔 19.3ms，未收到 longtask。收益是页面响应，不是把整个等待时间缩短一倍，也不是严格隔离的编码器单因素实验。

实际生产 UI 的观测范围更广：Edge 4K 6.55 秒、最大 rAF 66.7ms、无 longtask；8K 22.43 秒、最大 rAF 183.4ms、56ms longtask。Chrome 对应 27.73 / 74.72 秒，最大 rAF 216.8 / 383ms，8K 有 112ms longtask。后台剖析此前也出现 344–403ms 停顿，不能只引用后续 35ms 样本。两浏览器时长差异尚未充分归因，保留全部结果；支持持续反馈和取消，不声称任何设备绝对流畅或所有 8K 操作已商业通过。

## 接续

用户新要求优先：从完整签名重新绘制超清 PNG，研究逐条带压缩避免 16K 整幅 Canvas，并分别处理字体原生轮廓与上传笔迹的来源清晰度。整幅 SVG 不作为默认超清浏览方案；不能通过放大旧 PNG 承诺新增笔画细节。低内存真机、真实手写、实体打样及六方向商业验收继续。
