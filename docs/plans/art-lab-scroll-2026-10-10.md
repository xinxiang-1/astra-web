# 探索六种表达：页面滚动与路由恢复

用户再次反馈首页「探索六种表达」进入的 `/art-lab` 无法下拉。本阶段针对页面滚动，保留已有作品渲染、模式、导出与首页 Studio 参数。

## 排查事实与修改

此前阶段已将探索页移出固定高度的字符编辑器布局。当前开发服务及生产预览在 Edge 直接打开时，原有桌面和手机宽度滚轮合同均通过；因此没有声称在用户设备上复现了同一种故障。

仍存在一个可复现的兼容性缺口：`body` 默认 `overflow: hidden`，只有 `body:has(.app-shell.scrollable)` 才允许滚动。移除这条规则、模拟浏览器忽略 `:has()` 后，页面保持隐藏溢出，滚轮操作前后 `scrollY` 都为 414。这个受控实验验证的是 CSS 依赖，不代表已确定用户浏览器版本。

修改如下：

- 页面默认允许文档滚动。Vue 根据当前路由直接维护 `body.page-scroll-locked`，字符编辑器及沉浸特效页才锁定文档滚动；应用卸载时移除标记。全屏已有的临时内联锁定继续生效。
- 探索页预览工作区改为具名 `section`，避免在应用主内容内嵌套另一个 `main`，也避免继承应用针对主内容的最小高度规则。
- 移除探索页自身无高度限制的 `overflow: auto`，由文档统一滚动，保持桌面双列和手机预览优先的布局。

## 验证与失败记录

`npm run type-check`、相关 ESLint、脚本语法检查、`npm run build`、Impeccable 检测与差异空白检查通过。构建仍有原先的 JSZip `stream` 浏览器兼容提示、签名布局混合导入提示及大 chunk 提示。

[最终浏览器记录](../validation/2026-10-10/art-lab-scroll/report.json)包含 Edge / Chrome × 1440×700 / 390×844 × 亮色 / 暗色，共 8 组生产预览验证：

- 从首页入口进入及直接进入；忽略 `:has()` 规则后依然可以滚动。
- 桌面鼠标位于预览画布上时滚轮下拉；手机宽度通过 Chromium CDP 连续触摸事件在画布上滑动。
- 主内容获得焦点后的键盘翻页；六模式切换、中文字段和环境动效选择；末尾操作及说明可以到达。
- 进入完整编辑器时文档锁定；浏览器返回探索页后恢复滚动。
- 单页头、单 `main`、没有横向溢出、没有浏览器运行时异常。桌面/手机明暗截图已分批目视检查。

另外使用真实路由交互复核彩烟 → 首页 → 探索页：彩烟为 `body overflow: hidden`，返回探索页后为 `auto`，滚轮滚到 436px。

保留了两次自动化失败及修正：[阶段摘要](../validation/2026-10-10/art-lab-scroll/summary.json)。第一次键盘测试紧接尚未完成的原生滚动，等待滚动稳定后再翻页通过；第二次 `Input.synthesizeScrollGesture` 在本机只生成触摸开始和结束，没有触摸移动。改用 `Input.dispatchTouchEvent` 连续移动后，同一页面实际滚到 510px。首次全页截图从下方位置捕获时带入了视口外的固定跳转链接，随后从顶部截图，未因此修改产品样式。

手机验证属于 Chromium 内模拟触摸，不覆盖物理手机或 Safari。该阶段没有重新验收高级动效性能、登录、会员、支付或部署。

## 复现

先确认生产构建与现有预览一致，再在前端仓库运行；输出目录按阶段另起，避免覆盖旧证据：

```powershell
$env:ASTRA_PREVIEW_URL='http://127.0.0.1:4210'
$env:ASTRA_SCROLL_OUTPUT='output/playwright/art-lab-scroll-next'
node scripts/art-lab-scroll-contract.mjs
```

相关实现与验证输入的 SHA-256 见[源文件清单](../validation/2026-10-10/art-lab-scroll/source-manifest.json)。下一步继续现有真实后端会员联调和渲染性能阶段；本次只提交滚动修复及它的文档、证据。
