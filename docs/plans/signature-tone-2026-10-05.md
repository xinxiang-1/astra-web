# 签名画像的笔迹浓度与彩墨

用户反馈有一种签名画像颜色偏淡。未获得具体模式信息，本阶段在默认纸上书写复现，并同时验证夜光和镂空。默认 woven 的实测笔迹覆盖率控制透明度：画像越亮，签名越透明；细笔迹又留下大量纸白，缩小后平均颜色更浅。原“局部染色”使用深墨变换，而非原图RGB，因此彩色照片还会丢失鲜明色彩。未发现预览CSS重复透明或后台绘制漏色。

## 实施

保留原效果及原排布，在常用设置加入1–3×“笔迹浓度”，预览区增加“增强笔迹”（至少1.8×，应用当前参数）。使用 `1 - (1 - alpha)^gain` 平滑增加墨量，1×严格保持旧计算，零墨仍为零、满墨仍为一，中间层次保持严格递增，不用线性倍乘直接截平暗部。名字落点、模板、尺寸、方向、画序和原深度不变，woven / stipple 都支持。

折叠色彩面板提供“墨色层次 · 原效果”和“原图彩墨”。后者把实际采样RGB记录为literal墨色，避免重复压暗；自定义边缘墨和夜光浅墨继续优先。原图彩墨仅在局部染色开启的纸上书写可选；笔迹浓度适用于两种底色和普通 / 镂空签名。没有添加照片底图或额外填色。

新参数进入生成快照、JSON、`.astra-signature`校验和控件恢复。浓度及彩墨选择不监听即时重绘，点击生成或一键增强才应用，避免拖动时反复提交绘制；现有后台精绘、反馈与缩放档位继续使用。浓度和literal色均固化到Placement，因此预览、Worker、PNG及Path SVG消费同一作品，加载旧作品缺省为原效果。

## 诊断与验证

固定2K布局、40写法和900px实际输出，两个仓库画像的1× / 1.8×结果如下。“明暗差”是输出像素相对纸白的平均最大RGB通道差，不是商业审美评分。

| 画像 | 枚数 | 原平均笔迹强度 / 增强 | 原明暗差 / 增强 |
| --- | --- | --- | --- |
| portrait-reference.png | 18447 | 0.635 / 0.814 | 16.47 / 21.24 |
| portrait.jpg | 18512 | 0.389 / 0.559 | 9.46 / 13.52 |

同图浓度增强约29% / 43%的平均明暗差。原图彩墨用于恢复色相，而非保证任何照片比深墨更暗：上述较亮画像的原图彩墨明暗差为10.21，低于1.8×深墨的13.52。签名覆盖率和素材高亮限制仍存在，不能据此宣称完全复现原照片或全素材商业画质通过。

新增 `test:signature-tone`。Edge / Chrome各14组：六种woven / flow / stipple × 纸 / 夜计算默认逐项等于冻结 `abd3499`；增强和彩墨几何保持；8种笔迹 / 底色 / 彩墨组合分别对冻结渲染器输入同一增强Placement，同步、分块、普通笔迹Worker RGBA零差；SVG完整签名数量与透明度保持，未嵌照片。101级渐变在1× / 1.8× / 3×均严格递增。

第一次合同把同步整图与透明分块结果直接要求零差，触发失败。两种既有栅格路径的合成舍入并不相同，修正为同一路径、同一增强输入对比独立冻结渲染器，并让Worker对比相应分块路径；零差门槛没有放宽。此合同不宣称同步与分块在所有素材逐像素相等。

两浏览器实际页面10写法、2K彩色测试画像共13610枚名字。一键增强PNG改变而几何不变；未应用彩墨选项时下载仍用生成快照；彩墨PNG、Path SVG和作品文件实际下载，重开新参数与PNG hash完全恢复。1440px / 390px及两种UI主题无页面横向溢出。原响应式合同20组、100写法16074枚生成、三档高清缩放、取消通过。其计时期间部分与其它QA重叠，不用于本阶段性能承诺；单独构建页面的增强响应观察另存证据。

单独构建页面增强观测924帧，rAF间隔P95为17.5ms、最大79.3ms，20ms定时器最大间隔76.5ms，加载反馈实际可见；拖动浓度不提交后台绘制，完成后2秒无新增请求。这是本机Edge观察，不保证所有设备或素材无卡顿。

产品type-check、相关ESLint和build通过。[精简证据](../validation/2026-10-05/signature-tone/)保存双浏览器合同、诊断、响应式回归和单独生产页观察；原始PNG / SVG / 作品文件保留在本地 `test-results/signature-tone-*`。

## 限制与下一步

本阶段提供可控浓度与原图彩墨，默认继续保留用户认可的效果。真实手写稀疏签名、极亮图片、8K印刷、Safari / 真机和全素材审美尚未认证。后续以用户实际偏淡模式与素材进一步调整；不重启已停止的容量、atlas或软件tint研究。
