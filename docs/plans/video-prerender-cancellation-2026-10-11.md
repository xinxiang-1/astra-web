# 视频定位取消与任务归属

接续[视频性能路线](./video-gpu-pipeline-2026-10-10.md)和[还原品质 GPU 阶段](./area-gpu-preview-2026-10-10.md)。本阶段处理高清预解析一直等待、取消无响应及旧任务覆盖新素材的问题；缓存分页、持续帧率与真实设备仍继续验收。

## 原因与实现

此前 `seekVideoTo` 只等待 `seeked/error`，没有取消或超时。移除视频、换源或解码定位不结束时，解析无法退出；取消/失败后的 `finally` 再次等待恢复定位，也可能继续挂起。页面共用取消布尔值，旧任务的进度、结果和清理没有完整的素材/任务归属。

1. 定位增加 `AbortSignal`、兼容 `shouldAbort` 的等待中检查、默认 10 秒超时，以及 `emptied/abort` 处理；非法时间和定位赋值异常也释放监听与定时器。`currentTime` 是请求位置，仍在 `seeking` 时不能视为解码完成；旧 `seeked` 迟到时也先检查 `seeking`，避免提前完成新定位。
2. 解析在定位、转换、栅格完成后检查取消。记录源身份；换源不恢复旧时间，同源被新任务接管也不能恢复。成功时有界等待恢复；取消/失败时直接请求原位置，立即释放任务，不再等待可能失效的定位事件。
3. 每次页面解析拥有独立 controller、generation、源版本、元素和参数键。取消立即解除加载；参数、选段、帧率、预览模式、换素材和卸载撤销旧任务。只有当前任务可以更新缓存、错误、播放和进度。
4. 恢复期间不采样仍在定位的视频；恢复转换也校验归属。取消后立即拖时间轴会撤销旧恢复，保留用户的新位置。旧视频元素的事件不能更新新素材。
5. 普通取消用适配双主题的 `role=status` 提示，超时/解码失败保留 `role=alert` 与重试路径。当前作品保留，加载期间可取消或替换素材。

保持六模式采样、列数、画质、帧率、原色与现有缓存预算。首页保护范围和已认可按钮 hover 保持；免费导出继续免费，用户素材仍在本地处理。

## 失败、验证与证据

新增核心合同在 Git HEAD `0b8bb8e` 的真实模块上运行：初版 24 组中 21 组失败；加入迟到 `seeked` 守卫后，最终 25 组中 22 组失败。正常定位、媒体错误和成功预解析三个控制组通过。失败包括等待超限、残留监听及取消/旧恢复缺口；场景数不等于独立缺陷数，两版原失败均保留。

修复后 Edge 155、Chrome 154 各 25 组通过，每组媒体/信号监听、timeout/interval 全部清零，迟到进度为零；受控 `EventTarget` 只模拟定位边界，不冒充真实解码器。当前守卫与统一 MP4 的六模式 typed-frame 缓存、取消/内存拒绝及源时间恢复回归通过。

真实页面验证双主题、1440px/390px、挂起定位中取消、真实默认 10 秒超时与重试、换图片/视频、旧任务迟到、取消后立即调整时间轴及离页。开发合同检查 Vue 状态/作品身份，并补帧率、选段的内部失效守卫；正式构建只检查公开 DOM、原生视频和 Canvas，参数失效用实际清晰度按钮。正常取消须在 1.5 秒内解除加载，替换图片后的像素一致性始终保留。

测试基础设施的失败也保留：Chrome 初版生成了 110-byte 空 WebM，页面正确提示解码失败；可见 Canvas 与主动 `requestFrame` 改进后仍再次出现 110-byte 文件，原生解码在素材阶段及时拒绝。另一次有效 WebM 的图片像素比较失败，测试仅等待加载层消失和 100ms 像素稳定，可能在 Worker 完成前取样；改为同时等待公开 `data-render-pending=false`，每次重新开始稳定窗口并记录取样时间/状态，未删掉或放宽像素断言。

最终统一使用本地 ffmpeg 合成的 H.264/yuv420p MP4（480×320、20fps、2秒、40帧），各轮复制相同字节并核验 SHA256，再由各浏览器独立检查 `loadeddata`、尺寸、可解码状态和实际时长。PNG 仍本地生成，素材不入 Git。报告包含当前脚本 `scriptSha256`、素材来源/哈希/格式及解码结果，旧脚本与各轮失败保留，不能将不同脚本版本的结果混为同轮通过。最终结果见[阶段证据](../validation/2026-10-11/video-prerender-cancellation/manifest.json)。

最终同一脚本与 MP4 的开发/正式 Edge、Chrome 四轮页面合同均通过，零页面异常。每轮四种主题/尺寸组合的最大取消耗时：开发 Edge 20.2ms、Chrome 13.0ms，正式 Edge 24.7ms、Chrome 14.6ms；正式默认定位超时约10.1秒，立即调整时间轴保留0.35秒目标，换源/新任务/重试/离页守卫通过。这些是合成素材下的操作恢复测量，不能外推任意解码器或设备的响应时间。

已有视频响应合同首轮在原色模式测得 208.8ms 心跳间隔，超过原 150ms 门槛；原失败保留，原因尚未证明。未修改产品或放宽门槛的独立诊断复验通过，含六模式、240列预解析、暂停稳定、等待反馈、全屏释放、390px及 Worker 回退。短合成素材的成功回归不证明持续帧率或所有素材都不卡。

类型检查、相关 ESLint、正式构建依[前端验收技能](../../.agents/skills/astra-web-validation/SKILL.md)执行。构建保留既有 stream 外置、混合动态导入、较大 chunk 和插件耗时提示。初次构建后补取消/时间轴恢复竞态，随后再补迟到 `seeked` 的 `seeking` 守卫；最终重新构建，正式双浏览器合同使用包含两项修复的最新产物。人工查看最终桌面/390px的亮色加载、暗色取消及超时错误截图，当前画面保留、双主题提示与无横向溢出通过。

复验入口（使用全新输出目录，原始失败不覆盖）：

- `node scripts/video-seek-cancellation-contract.mjs`：开发服务；`ASTRA_SEEK_BASELINE=1` 可验证 Git HEAD 模块，设 `ASTRA_SEEK_OUTPUT` 和 `ASTRA_BROWSER_CHANNEL`。
- `node scripts/video-prerender-cancellation-ui.mjs`：开发服务完整状态合同；正式预览设置 `ASTRA_VIDEO_CANCEL_DOM_ONLY=1`。设置 `ASTRA_VIDEO_CANCEL_INPUT` 为本人持有的合成 MP4/WebM 绝对路径，复制后仍独立原生解码验证；不设置则使用浏览器合成路径。用 `ASTRA_VIDEO_CANCEL_OUTPUT` 选择独立输出根，`ASTRA_PREVIEW_URL`/`ASTRA_BROWSER_CHANNEL` 选择服务和浏览器。
- 原 `scripts/art-video-cache-contract.mjs` 增加 `ASTRA_CACHE_OUTPUT/ASTRA_CACHE_INPUT/ASTRA_BROWSER_CHANNEL`，可保留各轮独立证据；默认入口仍兼容。

## 边界与下一步

直接恢复 `currentTime` 是定位请求，不是解码完成；页面在后续 `seeked/canplay` 恢复采样，慢设备可能继续保留上一画面。10 秒错误上限针对每次定位，不是整个选段的耗时承诺。控件中的帧率数字不能证明作品达到该呈现帧率。

本阶段没有分页落盘、LRU、完整浏览器 heap 认证、10 分钟资源增长或真机验收，也不证明高清全特效持续无卡顿。继续推进这些资源与实际呈现门槛，同时按总计划接后端会员页面、offer/可信授予和实际云消费者、隔离 staging、真实渠道及部署推广。后端[接续记录](https://github.com/xinxiang-1/astra-cloud/blob/main/docs/plans/video-prerender-cancellation-2026-10-11.md)保持验证码、资金、权益和额度由服务端决定。
