# 固定光色字形复用研究

本阶段只修改独立研究脚本，没有接入生产绘制器。默认光晕使用固定色，但原色与彩色中文主图的染色表频繁淘汰后，光层也反复重染相同字形。候选为固定光色保存独立不可变位图，最多2MiB，与原主表共用16MiB像素预算；活动光色路径保持原绘制。原场、RGB、字形、画序及64项临时表不变；模板或格尺寸改变时失效，销毁时释放。

## 验证与失败

Edge / Chrome各72个六模式透明及不透明帧和12个释放记录，全部RGBA零差。180列原色和中文的实际输入帧成本存在混合结果，六个中段样本的P50 / P95如下（毫秒）。

| 浏览器 / 模式 | 原版 | 候选 |
| --- | --- | --- |
| Edge 原色 | 824.35 / 849.97 | 574.95 / 599.00 |
| Edge 中文 | 1670.90 / 1797.40 | 1988.85 / 2167.80 |
| Chrome 原色 | 2412.00 / 4122.55 | 1328.80 / 1789.43 |
| Chrome 中文 | 15405.60 / 16863.38 | 10940.80 / 11267.97 |

真实生产页上传、S形鼠标、停住、离开与恢复，各候选4个请求按实际时间戳和字形回放到原Worker，RGBA零差；光表实际命中，原色14字形21952字节、中文12字形29568字节。空闲无请求，交互中普通绘制提示无样本，恢复像素一致。

早期Edge等待期间轮询PNG读回；后续Chrome改为等待完成帧的指针强度，再单次检查PNG。两种首帧计时方法不同，不能横向比较。Chrome同方法内原色首次反馈10132 / 8600ms、中文18046 / 12451ms，恢复31474 / 25557ms、54183 / 41439ms（原版 / 候选）。虽部分改善，仍远未达到商业交互性能。Edge中文中段成本及首次反馈退化，候选不晋升。

独立拆解在主图与光层之间额外读回1像素，会改变批处理。冻结原色活动光层864 / 1417ms，候选57 / 46ms；冻结中文2069 / 2421ms，候选550 / 800ms。首帧主图成本也明显变化，所以不能把差值作为稳定加速比，更不能据此证明全部瓶颈已解决。浏览器随后单独启动的GPU元数据记录Intel UHD / ANGLE D3D11，Canvas2D等启用；该观察无法证明此前每个surface使用的后端，不将慢帧归因于已确认的软件后端切换。

## 实施与下一步

新增 `research:preview-light-material`，真实页脚本可选择材料候选与低读回等待，拆解脚本可选择冻结来源 / 模式并复制帧数组。相关脚本语法、ESLint通过；本阶段没有重跑产品构建或完整视频合同。[精简证据](../validation/2026-10-05/preview-light-material/)包含来源hash、同浏览器记录与释放结果。继续保留候选，生产保持原合同。最新用户反馈签名颜色偏淡，下一阶段优先排查签名颜色、墨量与实际显示。
