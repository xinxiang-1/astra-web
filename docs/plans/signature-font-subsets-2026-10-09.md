# 按中文名字加载字体分片 · 2026-10-09

接续[完整WOFF2与重试](./signature-font-web-2026-10-09.md)和[公共正文同源字体](./site-local-fonts-2026-10-09.md)。纯中文名字现在只加载需要的字块，保留原笔迹、缺字拒绝、名字配方与作品包身份。真实手写、复杂背景、印刷、真机和商业审美仍需验收；六方向、前后端、后台会员、真实认证/支付及部署/推广继续。

## 实施与边界

- 使用原六款固定SHA256的TTF和固定fonttools 4.60.2 / brotli 1.1.0，在U+4E00–U+9FFF内按256码点分块。每款81个有字分片，共486份WOFF2和6份有hash的目录；每款复制原OFL。原TTF、完整WOFF2和项目许可身份保留。
- 分片生成时逐个核对40,581个Unicode映射的解复合轮廓、advance/LSB、hint和全局几何指标。GSUB/GPOS逐表审计：这些固定源的CJK输入不参与跨字符排版；未来来源出现kern、其它lookup或CJK布局依赖时生成器拒绝，不能自动套用该拆分方案。
- 修改版内嵌字体名称改为`Astra CJK {id} {block}`，保留copyright/OFL元数据和原许可文件；原CSS family和font ID继续用于项目兼容。[来源与修改说明](../../public/fonts/signature/cjk/README.md)。分片私有数据携带自己的cmap，不是完整源cmap。
- 最长32字、全部属于基本CJK区的名字走分片。英文、混排、标点、扩展汉字和更长文本继续完整字体，保留原shaping；完整字体已加载或在加载时复用它，不再下载分片。
- 先核对目录SHA/尺寸/来源/覆盖/路径/范围，再核对所需分片SHA/尺寸/cmap，实际FontFace完成后才绘制。目录先拒绝缺字，不下载无效字符的分片。不通过平台字体悄悄替换书写风格。
- 目录和字块分别共享请求；一个调用取消不影响另一个调用。已取消的调用不发字体请求，失败缓存清除后允许同页重试，既有名字库和作品保留。

这是首载下载优化：新增分片16,144,476 bytes、目录95,792 bytes及六份许可，原字体仍保留，部署包增加约16.3MB。不同名字/字体/块数的收益不同，32个分散字符可能触发很多字块；不承诺所有文本同比减少。

## 浏览器验证

Edge154.0.4258.62和Chrome157.0.8081.0各一次最终分片合同通过：6字体×6中文名字×5尺寸/变换＝180组分片输出，另有90组英文/混排和30组完整字体后中文复用，共300组尺寸及完整RGBA与原TTF原生FontFace零差。名字包括李云舟、张思雨、林晓晚、欧阳修、一丁七、左右天地；18/72/240px和两种旋转/倾斜/缩放/字距组合不代表所有文本或设备。

每款逐个比较20,992个CJK码点与原TTF字表；缺字先报错且没有分片请求；16类畸形目录拒绝。目录503/同尺寸SHA破坏、字块503/同尺寸SHA破坏/截断共5类失败后同页重试通过。两调用共享一个目录和三块、独立取消及预取消零请求通过。生产入口验证失败重试、加载提示、六family按实际名字加载、新名字触发新字块，以及双主题桌面/390px布局；只请求分片及目录，无原TTF下载。

既有完整WOFF2合同两浏览器各180组像素、全Unicode覆盖、9类畸形文件、3类损坏恢复和共享取消通过。名字库合同两浏览器均通过：6组加载/输入/取消、完整姓名边界、确定性、事务失败/取消/冲突保留旧库、并发追加和真实页面刷新/390px。六字体/抠图合同两浏览器各5组通过：六款写法确定性、完整项目RGBA及配方恢复、六类控制背景提取、调整确认、整批取消和双主题手机。这些控制背景不是任意真实照片的品质证明。

类型检查、相关ESLint和两次生产build通过；第二次build纳入静态来源说明，两次输出JS/CSS文件名中的内容hash相同。build保留原有大chunk、动态/静态导入及stream浏览器兼容警告。产品/字体生成验证无失败轮次；归档首轮Git索引检查发现四份日志受`*.log`忽略规则影响未暂存，显式加入这四份日志后重新核对字节与范围。Edge core预检不累计最终样本，完整字体旧合同的额外性能数字也不混入上述分片结论。构建使用保留既有无关改动的工作区，未宣称它是干净生产发布包，部署时仍需隔离构建绑定提交SHA。

## 当次弱网测量

串行CDP禁缓存，524288 bytes/s、80ms延迟；单次行楷字体，“李云舟”三个字块与完整WOFF2比较。两浏览器完整WOFF2为3,279,386 bytes，分片加目录为167,895 bytes，body减少94.88%；HTTP开销计入transfer，分别3,279,686与169,095 bytes。没有HTTP压缩的目录仅占15,967 bytes；部署启用压缩时传输数值需重新实测。

- Edge：完整6535.6ms → 分片530.7ms；完整FontFace阶段92ms长任务，分片当次无≥50ms长任务，rAF最大16.8ms。
- Chrome：完整6532.5ms → 分片528.4ms；完整FontFace阶段89ms长任务，分片当次无≥50ms长任务，rAF最大16.9ms。

这些是该名字/字体的两次独立测量，不是六字体同时加载、完整画像生成/缩放、长时间统计或真实手机结果。不能宣称页面完全不卡或商业品质全部通过。

## 复现与接续

独立Python环境安装`scripts/signature-font-transport-requirements.txt`，执行`scripts/build-signature-font-subsets.py --output test-results/新的唯一报告.json --write-assets`。生成器拒绝覆盖旧报告及不同内容的已有hash文件；全部资产以目录hash和逐文件hash复核。

分片合同：开发5210 / 生产4210，设置`ASTRA_PREVIEW_URL`、`ASTRA_UI_URL`、`ASTRA_SUBSET_OUTPUT`、`ASTRA_BROWSER_CHANNEL=msedge|chrome`，执行`node scripts/signature-font-subsets-contract.mjs`。`ASTRA_SUBSET_PHASE=core`仅预检算法/故障/取消，不执行生产UI与弱网；最终报告使用all，预检不累计为最终通过。旧完整WOFF2合同明确使用拉丁文本强制完整通道，生产UI允许有hash的CJK目录但仍拒绝TTF；名字库合同要求每个目录/字块只请求一次，不能沿用“一整个字体文件一次”的计数。
