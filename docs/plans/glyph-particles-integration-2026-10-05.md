# 字符聚散接入与可携带作品

本阶段延续 [v9 可操作研究](./creative-research-iteration-2026-10-04.md)，将同一效果接入真实编辑器。整体六方向目标继续进行。签名方向、常用功能与主题组件见 [工作台](./signature-theme-workspace-2026-10-04.md)和[轮廓方向](./signature-direction-2026-10-04.md)；视频响应改进见[视频阶段](./video-responsive-playback-2026-10-04.md)。本阶段没有重启已停止的签名容量或视频彩色图集研究。

## 实现与算法

- 增加独立 `particles` / “字符聚散试用”。六模式、品质、普通/全屏、浏览器项目、`.astra` 与离线 HTML 携带相同参数；默认旧效果和历史项目保持。GPU 包装器将此效果交给共享 Canvas 工厂，视频绘制 Worker 也使用这个工厂。
- 原生 trail 场提供真实 UV/秒速度、UV 位移与密度。速度方向经每字固定的小角度转向，速度和密度共同决定目标散开幅度；逐字闭式阻尼弹簧保存位置与速度，输入停止后自然回到原字格。没有新增流体求解器、装饰粒子发射器或逐帧随机噪声。
- 预计算六个身份常量为 Float64，保持 v9 数学精度；八个动态状态为 Float32。每字格 80 bytes，131072 格上限为 10 MiB。预算包含所有字格，不能把它称为整体浏览器内存上限。超容量停止聚散和原生交互场，保留作品及环境设置，显示提示并允许触屏滚动；由用户主动调整清晰度，没有自动降列数或颜色量化。
- 使用字库与网格作为持续状态的身份，而非每帧对象引用。解码后新 frame 对象不会清空弹簧；字库或网格改变、时钟回退、零强度、销毁分别有明确恢复或释放行为。原生场结束后仍绘制粒子余波，直至自然归位。
- 字形保持正向、原 indices / RGB 不变；粒子明暗仅作用于实际字形。PNG/TXT 保留静态作品；MP4 仍导出环境动画和参数快照，不录制鼠标轨迹。真实交互录像独立采集并准确标记。

## 实际失败与修复

1. 首次 type-check 指出交互场可能为 null。粒子余波可以在原生场停止后继续，因此不能假定交互对象一直存在；无原生折射时先清零 native sample，再应用弹簧，旧拖尾分支明确要求 interaction。
2. 实际页面 R1 六模式聚散/归位、全屏与暂停已通过，但从暂停环境切回静态后，测试只等 pointer/interaction，可能早于下一次绘制读取基线。R2 改为先等真实画布 `data-motion=none`，再等待归位；精确像素门槛未改，R2 完整通过。失败报告的巨大 PNG 差异保留在本地，精简归档仅存摘要。
3. `.astra` R1/R2 图像恢复已通过，后续因本地 MP4 fixture 缺失而退出。先生成真实 640×360、15fps、3秒 H.264 素材，再运行完整合同；不能把缺素材的部分运行称为视频通过。QA 的 FFmpeg n8.1 压缩包按发布方 SHA256 核验，工具只留 ignored test-results，不改变产品依赖或系统 PATH。
4. 容量提示在离线 HTML 首次绘制后被通用就绪文本覆盖，且超容量仍锁触屏滚动。改为保留容量文本，并按实际 renderer 状态更新 touch-action；编辑器也按容量恢复滚动。文案不再称环境动画一定静止。
5. 检查旧作品包合同发现新 hover 只在图像部分选择。补齐视频的选择、包参数及重开画布断言，再验收视频恢复；不把旧合同的缺失覆盖外推为完整支持。
6. 超容量虽然停止模拟，编辑器和离线页仍可能因指针输入重复绘制静态作品。增加输入守卫与静态调度条件；独立容量复验在画布内部移动十次，编辑器 / 离线页实际绘制计数均为零，滚动仍允许。环境动画设置保持。
7. 完整作品包 R3 在原色 PNG 的30秒下载等待中退出，未处理的监听 Promise 抢先拒绝，导致完整失败报告未保存。改为 Promise.all 同时处理操作与下载，记录每次下载流程耗时，等待与现有媒体导出一样使用120秒；R4单独完整通过。原色流程仍测得34.4 / 50.2秒，不把这次测试修正当作产品性能修复。异常截图 / 报告路径保留，所有 hash 和损坏拒绝门槛不变。

## 验证

当前已完成：Edge 真实编辑器六模式鼠标聚散与 PNG 精确归位；普通/全屏交互与关闭资源释放；暂停环境仍交互；减少动效静止且允许滚动；390px 编辑器、全屏、离线 HTML 触控各 1 down / 10 move / 1 up / 0 cancel 并精确归位；实际免费 HTML 下载且离线零网络请求；真实 WebM 上传、Worker 后端、视频时间前进。

Edge Worker 六模式 × 透明 / 不透明共12组，400px / 48列，共888帧与主工厂最终RGBA相同，活动状态一致，约4.8秒模拟时间归位；每个消息均为新frame对象，字库和字格身份持续。此矩阵不包含新解码后的不同颜色序列，也不外推到所有品质或4K。

Edge完整 `.astra` 合同：10组模式 / 品质的真实PNG精确恢复、参数一致、刷新恢复；17类损坏原子拒绝，重复导入和存储失败保留原行，旧项目不自动升级；真实 H.264 源的0.2–0.7秒片段、暂停时间0.2、聚散参数和重打包保持；390px无横向溢出、实际下载通过。全流程零POST请求。不是跨设备或商业审美认证。

真实MP4导出为1280×720、H.264、0.533333秒（15fps离散帧），选段0.2–0.7秒。第3帧归一化MAE为0.0030860，既有门槛0.04未改；忽略 / 错误速度 / 错误强度 / 错误风格误差分别0.0611395 / 0.0193665 / 0.0610931 / 0.0261107，全部满足既有优于错误参数的门槛。HTML携带particles；这些结果证明环境动画和参数快照，不证明鼠标交互录制。

最终容量守卫后的type-check、相关ESLint和生产build退出0。

Edge与Chrome最终各24组数值（六模式，光影/原色四品质，其余经典，透明/不透明）：每浏览器720帧输入与冻结 `c7f1eb2` 工厂 + v9表现逐帧RGBA相同，自然归位和零强度精确，原字形indices和RGB不变，旧trail对照相同。字格状态204800–322560 bytes，释放后0；每帧对象克隆仍有持续聚散。原生求解器源码body及三个保护源与冻结基线相同。这批报告生成于绘制分段改造之前，后续共享绘制与Worker验证见[后台分段记录](./video-render-slices-2026-10-05.md)。

生产构建Chrome R1通过光影 / 原色真实鼠标聚散和精确归位，但中文铺字在释放后的60秒归位等待超时。单独R2等待真实mode后仍失败：571×713、180列、phrase/classic、无环境动画、pointerStrength=0，interactionActive仍true；模式时钟仅推进2.25秒，交互时钟12.6206秒。不能将失败归因于R1并行资源竞争，也没有延长归位等待、降低列数或像素门槛。生产Chrome完整交互矩阵未通过。

进一步单幅profiling发现，尚未发生实际聚散的彩色中文初始绘制也需19.325秒：19450次目标drawImage累计15.72秒；临时颜色图块17951次未命中，6808项缓存占15.998MiB。瓶颈首先在基础彩色逐字绘制，不能简单归因弹簧。目标CPU后端无速度收益；扩大缓存首帧47.35秒，后续仍约6秒；每次未命中转临时bitmap首帧54.61秒，提前停止。均未采用；先前颜色软件着色存在像素差异，HTML surface更慢，亦已撤回。没有重开已停止的彩色图集研究。

后台分段改造解决有进度的长帧被12秒watchdog误判的问题，并提供当前视频帧进度；它不能证明同步图片的彩色交互已流畅。当前图片仍使用同步Canvas，这项限制明确保留。

实际生产编辑器录制VP9 WebM：571×713、321961 bytes，34个可解码帧，packet时间0–21.308秒。真实鼠标路径和自然重组可见，Native MediaRecorder请求30fps不等于实际恒定帧率，录制还包含真实页面和截图等待；没有据此宣称60fps或正式宣传片。录像hash和失败范围均保留在[精简证据](../validation/2026-10-05/glyph-particles-integration/)。

## 限制与下一步

试用接入不等于用户审美或整体商业验收。开发截图可辨识瓷像与原字符，局部快速划动会暂时让面部细节让位于散开，衣肩保留主体；仍需更多自然素材和实际用户反馈。当前没有 4K 持续交互、真机、长时间视频、所有显卡或任意环境叠加的性能认证。容量预算解决分配边界，不能证明容量以内必然流畅。

生产构建仍有已有 stream 外置、较大 chunk 与 signature layout-compute 无效动态导入警告。首页三个保护源、原生 Studio 参数及用户认可的 FxButton hover 不变。阶段完成后独立提交、立即推送并官方读回 SHA；原创案例、素材与其余商业交付继续。
