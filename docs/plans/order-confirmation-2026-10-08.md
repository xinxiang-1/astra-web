# 购买确认与原订单请求恢复

2026-10-08，接续[订单详情与支付记录恢复](./order-recovery-2026-10-08.md)。本阶段接通商品详情 → 阅读完整条款 → 显式确认 → 后台订单快照 → 订单详情。真实收款、会员、退款及部署目标继续。

## 实施与权限边界

`/collections/:slug`显示后台选定版本、整数分金额、交付文件和三份完整条款。订单确认独立于付款；新增后台能力字段`orderCreationEnabled`与实际订单创建服务保持一致：production为false，其他环境允许测试订单。付款、mockPayment和creationKitReady原有能力标志保持false。创建工作流仍需creationKitReady，无法读取能力时不提供新订单确认。只根据后台字段展示入口，后台仍独立检查身份、账户状态、商品/政策版本、未结订单、权益和频率。

确认页初始不勾选同意，显示使用许可、购买条款、退款说明全文，再明确勾选才能提交。切换所选版本、刷新目录、退出核对或账户变化都会清除勾选。POST只提交skuId、offerVersion及三种政策version，绝不提交价格、数量、权益或付款状态；金额、时间和交付快照由后台确定。创建成功仅表示有订单，不触发支付、私有下载或权益授予。测试环境明确提示不涉及真实付款。

第一次发送之前，将UUIDv4及**原五字段请求**保存到sessionStorage，按令牌SHA256和商品slug隔离；不保存令牌原文、金额、条款全文、付款码或权益。未确认请求不能被另一所选版本覆盖，手动恢复沿用原请求与原键，目录更名/下架不重构历史请求。收到合法、绑定原SKU/政策及金额一致的订单后保存orderId，刷新恢复只GET原订单；不自动重试写入。响应丢失、503、401、幂等冲突或其他不确定结果保留原记录，不当作未下单。存储失败阻止初次POST；损坏记录阻止新请求，提示从我的订单核对。保存结果失败也保留既有原命令，不静默生成新键。

只有明确版本冲突43002会释放本次原请求，因为后台同键重放先于版本校验，此结果证明该键没有成功创建订单。用户必须刷新内容、重新阅读并确认。43003/43004等已有权益/未结单冲突保留记录并提供账户订单/已购入口，不解析错误文案里的订单号作为授权依据。

后台已确认CLOSED的原订单可显式“重新核对新订单”；先GET再次确认CLOSED，再清除本标签页原记录，重新展示当前目录并要求新的同意。待付款或已付款订单没有此入口。清除记录不代表服务器取消订单。恢复模块在目录404/503时也保留入口，仍可核对原命令；令牌变化、跨标签页切换和离页会取消或丢弃旧身份结果。登录returnTo仅增加合法80字符以内商品slug，查询、fragment、编码、外链和多值仍拒绝。

## 真实验证、失败与修复

12项命令持久化/丢响应重放/GET恢复/绑定/存储/损坏/账户/关闭/返回路径合同通过，前序10项付款恢复合同仍通过。type-check、相关ESLint和production build通过；首页三保护源无差异。

真实隔离MySQL/Redis/system/gateway运行5项JUnit、11项实际Edge浏览器检查；51条实际HTTP全部通过现有OpenAPI、no-store和requestId复核。浏览器只有GET与POST订单，数据库断言为3笔订单（包含预先由后台到期关闭的1笔）、0支付、0权益、0outbox。同键并发4次只1订单，production切换和商品下架后仍恢复原固定订单与原快照，真实Redis中断503后原键恢复成功。

浏览器先展示三份完整条款和未勾选同意；实际已受理200后丢弃响应，刷新同标签页不自动写入，再双击只发一次同键恢复。已知orderId刷新只GET。明确注入旧目录offerVersion1，实际后台版本2拒绝409；刷新后同意重置，重新确认新版本才创建另一订单。第二真实标签页切换账户清除原订单显示，后端404；退出账户不恢复他人记录。预先真实创建/到期关闭的订单以明确夹具记录放入本标签页，再由两个真实GET验证旧单与CLOSED门槛，重新确认不额外写入。

构建R1失败：格式化把模板的多条事件语句改成无效表达式；改为独立leaveReview函数后R2成功。联调R1在新构建完成前启动，浏览器加载了旧preview且等不到新组件，1浏览器测试失败，其他4后端测试通过，独占资源正常清理；随后确认构建完成再运行，R2通过。补关闭订单重新确认后R3通过；R4仅将截图收敛到订单组件，避免整页截图包含视口外的固定跳转链接，最终验证保持通过。原始失败/中间日志保留于项目外tmp，成功精简[证据](../validation/2026-10-08/order-confirmation/README.md)独立归档，不覆盖前序证据。
