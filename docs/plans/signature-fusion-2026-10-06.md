# 偏淡实际素材诊断与浓彩融合

用户提供了实际偏淡原图/8K输出，并明确选择“优先画面浓郁，可接受明确标注的彩绘底色＋真实签名”。原文件保留在用户路径，测试输出只在ignored test-results；没有将私人照片或其衍生图像加入public/Git。

## 实施

新增可选“浓彩融合”及一键按钮：原图生成最长384px的彩绘底色，以默认75%混入纸/夜底色，再画完整签名。底色10–85%可调，纯签名为0；不更改原Placement、墨色算法或默认纯笔迹。384² RGBA上限576KiB，按原图对象WeakMap复用；Worker传输独立像素副本，背景绘制后的临时surface释放。普通笔迹继续后台，镂空保留原响应式Canvas；GPU未经核验不使用融合。

预览、高清区域、PNG、Path SVG及.astra-signature按生成快照消费同一底色/浓度。SVG显式嵌入小底色PNG，同时保留每枚签名路径，UI说明属于混合画面。项目underlay校验由只允许0扩至0–.85，旧文件/缺省继续纯签名。调整选择/滑块不自动重绘，手动生成或一键融合才应用；原加载反馈继续。

## 验证与实际改善

Edge / Chrome各12个工程组合：纸/夜、普通/镂空、0/.75/.85。作品恢复RGBA零差；普通笔迹Worker完整输出及放大区域分别与同路径Canvas逐通道零差；SVG只有融合有一个image，签名数保持；非法浓度拒绝。没有将同步整图/分块旧采样差异混比。首次UI测试在slider.fill('.85')因Playwright格式校验失败，修为'0.85'，产品未因该错误修改。

两浏览器实际素材、10种字体辅助写法、2K输出15,996枚签名：纯笔迹3×与75%融合全部Placement逐项相同，PNG不同；未应用滑块/纯签名选择时导出保持，保存重开PNG hash完全相同。两宽度/两主题无横向溢出。字体辅助样例不冒充真人手写。

同输出尺寸的平均sRGB加权亮度（越高越亮）：

| 区域 | 纯签名3× | 融合75% |
| --- | --- | --- |
| 全幅 | 221.18 | 148.38 |
| 头发 | 208.96 | 88.38 |
| 脸颊 | 225.19 | 169.17 |

这些是本次指定区域，不是色彩准确度/商业审美评分。与用户原8K输出不能直接计算跨分辨率提升；同素材同2K对照显示颜色明显增加，原生名字完整。开发Edge融合完成约7.14秒、Chrome12.07秒；rAF间隔P95约16.8ms，最大83.3/100.1ms。这里只证明本机仍有UI响应，不能称字符绘制60fps或绝对无卡顿。

原浓度/彩墨冻结回归Edge14组及实际PNG/SVG/项目恢复通过。产品type-check、相关ESLint、build通过；原JSZip/stream、chunk、动态import提示保留。生产构建Edge / Chrome UI也通过：PNG hash与开发相同、快照及恢复一致；Chrome三档实际高清缩放通过。生产融合完成约8.17 / 11.71秒，rAF间隔P95约16.8ms；Chrome单次最大rAF间隔466.57ms、20ms定时器最大67.3ms，保留尖峰，不宣称全过程绝对无停顿。[精简证据](../validation/2026-10-06/signature-fusion/)保存实际数值和区域。
