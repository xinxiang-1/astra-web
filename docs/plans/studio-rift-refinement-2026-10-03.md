# Studio撕裂响应与局部形变打磨 · 2026-10-03

接续8f4a9c5原型。用户要求全面改善动效；整体商业目标仍active。本阶段只处理实测原色响应慢、强撕裂局部拥挤和原型空闲重复绘制，不将候选宣称为正式产品或用户审美通过。

## 实现前范围

1. 冻结8f4a9c5渲染器和v7表现层，历史v7不随生产优化改变。新v8以相同作品、列数、尺寸、品质、强度、范围和真实事件与v7并排。
2. 先测固定素材112列/720px的完整绘制耗时、tile命中/未命中与实际染色/光层成本；诊断插桩只在独立浏览器执行。不得减少列数、量化RGB、改变字形/透明度或降低画质来制造收益。
3. 根据诊断改共享绘制缓存，内存明确有界且销毁释放。与冻结8f4a9c5逐像素比较经典/精细/软件、六模式、透明/有底、旧Studio/环境效果/真实hover；原生求解完整函数和首页三保护源保持。
4. 新表现层约束局部位移梯度，避免面部字形集中和几何折叠，仍保留明显撕开、真实速度响应、原字形反光和自然归位。明确工程约束与实际视觉观察的范围，不以数值代替审美。
5. 原型按需绘制：空闲与暂停环境时停止无效绘制；指针/控件立即恢复，余波继续直到精确归位，真实时间戳、合并事件、隐藏/恢复、触控、减少动效与全屏保留。
6. 新独立合同、实录和动态审查，产品类型/相关lint/build及必要输出回归。精简证据归档、明确文件提交后立即用xinxiang-1推送并官方MCP核验；保留真实失败。正式项目/作品包/HTML/视频参数接通、其它创新与商业交付继续下一阶段。

## 实施记录

1. 112列/720px固定人像和多色图诊断22个热帧。人像经典/软件完整帧P50为26.4/20.7ms，多色为60.6/33.8ms；插桩会增加成本，不用于最终收益比较。多色经典4939缓存、12,722,864bytes，未耗尽16MiB；热点包含字形绘制与光层，并非styleColor探针。
2. 尝试1024共享可变图集，仍原RGB/字形并有16MiB预算。结果多色经典P50升84ms，峰值178.3ms；12同帧检查均有差异，首帧2517个通道不同、最大12。方案真实失败，已完整撤回，不更改像素门槛。诊断原报告保留独立sandbox。
3. 冻结8f4a9c5工厂，仅类型导入路径改变；v7主程序改用该冻结工厂，表现层逐字保留。v8左侧用冻结v7工厂/表现，右侧当前候选。第一次v8浏览器准备超时，原因import别名previous与时钟变量重名；改为previousRenderer修复，保留失败。
4. 新候选投影相邻位移的过大差值，交替方向8遍，再以双线性四角的梯度范数.72约束残差；保持正向字形、原色反光及原场回弹。该约束针对环境关闭时的撕裂映射，不宣称叠加任意环境形变后仍有同一几何保证。
5. 当前试验同帧精确double形变缓存，glyph/面积/光层可复用；73bytes/cell、上限4MiB，尺寸变化失效，大尺寸直接计算，destroy释放。是否保留由交替完整帧实测决定，不能凭独立非配对日志宣称提速。
6. v8环境关闭/暂停且无事件/活动场时停止重绘，真实时钟仍更新；指针事件唤醒，活动场继续到归位。画布离屏/隐藏仍暂停时钟，恢复按原生有限步进；减少动效/触控释放/全屏继承再验证。
7. R1有效合同：10模式/适用画质×12帧逐像素一致，四组交替32完整帧（8热身/24计时）及零强度/归位通过；独立插值正向验证和6模式×2强度通过。R1完整P50改善1.9%–6.6%，部分P95反而升高。R2保留全部输入/门槛，P50改善9.7%–24.7%、P95四组均降低；两次不同结果说明收益幅度不稳定，不宣传持续帧率或统一提升比例。最终R2多色经典62.7ms、软件32.1ms，仍不足以认证桌面60fps或手机/4K。
