# 签名来源字节冻结与 R2 声明 · 2026-10-04

R1 提交后逐个比较 Git blob 与冻结报告：五份源码/PNG 完全一致，下载 SVG 受全仓 `text=auto eol=lf` 影响，CRLF 从 5,992 字节规范化为 5,931 字节。为这一份历史来源添加精确 `-text` 属性，重新加入已核验的原始字节，避免跨机器检出与来源 SHA256 不一致；原报告、SVG 几何和算法不变。检查 Git blob 字节数与 SHA256 回到冻结值，不需要重跑绘图管线。

第一次普通 add 没有重写未改工作文件的 index，字节核验失败；随后使用精确文件的 `add --renormalize` 才取得原始 hash。原 CRLF 触发 diff-check 的行尾空白提示，为这一个来源设置 `whitespace=cr-at-eol`，保留作者原字节且继续检查其它空白。最终 index 的 5,992 字节和原 SHA256 相符，差异检查通过。该失败与修复保留，不宣称第一份属性提交已经恢复了文件字节。

字节修复提交 `b89c31abbed2cea599e48b56ee41fa09ad517218` 已推送并通过 GitHub 官方接口核验。命令行直连先发生连接重置和两次443超时；诊断发现 Windows 系统代理存在而 Git 未使用，以单次 `-c http.proxy` 接入现有系统代理后推送成功。未全局改 Git 网络配置、重设密钥或暴露 Token；只读诊断仅输出代理主机/端口与 Token 是否存在。
