# GPU 不可用时跳过无用字符命令

继[还原品质 GPU 阶段](./area-gpu-preview-2026-10-10.md)，发现其 Worker 一直提供 `rasterBatch` 回调；没有 WebGL2 时仍生成逐字符几何及 Float64 命令，再由空 GPU 回调拒绝，最后执行完整 CPU 栅格。上下文丢失、纹理或输出超限也有相同额外工作。它不会改变成片，却给兼容设备增加运算和临时内存。

增加只读能力预检：GPU 上下文状态、纹理尺寸与原有 4MiB/32MiB 预算通过后，才构建命令。显卡纹理上限在初始化时读取一次；Worker 的空 GPU 直接拒绝预检。预检不推进原生交互场，不调整源帧、画质、列数或帧率，不减少 CPU 回退的实际画质。8MiB 命令限制及既有 GPU 异常处理继续生效。

实验 `area-fallback-20261010-r1` 从 `9745286` 冻结六个相关文件，在 sandbox 修改后三文件晋升；开发样本为仓库瓷器图、32列原色还原，320px输出，Microsoft YaHei、1440×960/DPR1、Edge154，固定三个时间和指针输入。预算五项场景、每帧固定时间、90秒截止、零模型调用；这是资源/一致性回归，不是多素材留出审美评估或持续帧率比较。

同一新增合同在修复前首先失败于无WebGL仍生成命令，失败保留；候选与正式源均通过：

- 无WebGL、context loss、模拟低纹理上限：各三帧 CPU 输出逐像素相同，GPU 绘制调用0，命令数组0字节。
- GPU可用：三帧实际GPU绘制，命令46080字节，最大像素误差2/255，保持既有一致性范围。
- 超输出预算：仅测试8192×8192能力拒绝，不分配或尝试绘制巨型输出。

复验：`npm run test:art-area-fallback`；可用 `ASTRA_AREA_FALLBACK_OUTPUT` 指定全新证据目录，开发服务默认localhost5173。相关type-check、ESLint及生产构建通过；已有57项GPU/CPU面积滤波合同随后复验通过。精简[证据](../validation/2026-10-10/area-fallback/manifest.json)记录源哈希及实际检查，原始sandbox不批量提交。

本阶段没有重新测GPU可用时的完整编辑器呈现间隔，不把上一阶段的r4耗时当作本次重测；它修复兼容回退浪费，不能消除原生场/逐字符CPU开销，也没有证明高清全特效60fps或10分钟持续稳定。后续仍按[总体路线](./video-gpu-pipeline-2026-10-10.md)处理场与几何计算、缓存分页和实际设备验收。受保护首页及其默认参数未改。
