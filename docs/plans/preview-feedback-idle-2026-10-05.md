# 字符画空闲调度与生成提示

接续[聚散真实时间阶段](./glyph-particles-clock-2026-10-05.md)，优先处理用户测试发现的“正在绘制字符画”频繁出现。真实生产页面中，180 列原色字符、鼠标静止、聚散位移为零时，12 秒仍提交 6 次完整绘制并出现 6 次提示，累计可见约 9.4 秒。后台计算确实存在，问题来自页面调度和提示的判定。

## 实现

- 指针强度收敛到目标、没有新输入且共享交互场已静止时，停止请求相同画面；误差小于 `.002` 时准确收敛到目标。再次移动和离开仍启动绘制，保留自然余波与精确归位。
- 每个画布记录实际完成的配置。初帧、新来源、参数或尺寸变化才显示生成等待；hover、环境动画和连续视频帧继续呈现完整结果，沿用真实 pending/进度数据。换图、释放画布和卸载会清理记录；视频完整结果呈现后立即更新提示。
- 补测发现默认光晕也受旧 `.15/.25` 秒时钟截断影响：真实高密度探针最终 RGBA 零差，但归位流程约 176 秒。光晕现在与聚散同用真实事件时间和原生 `.05` 秒步进，长间隔可分段补算；图片输入优先，完整帧期间空闲 tick 不覆盖排队手势。Worker 验证合法光晕补算，经典光晕不能伪造交互进度；离线 HTML 使用相同时间合同。

没有修改原生场 body、字形、中文句序或 RGB，没有降低列数及像素门槛。首页三保护源、Studio `.65/.38/.45`、已认可的 FxButton 和免费输出保持。

## 验证与实际失败

[精简证据](../validation/2026-10-05/preview-feedback-idle/README.md)保留前后真实复现、失败和最终报告。

Chrome 154.0.8037.57、Edge 154.0.4258.53 的最终生产 UI 合同均通过：180 列原色聚散静止 3 秒零请求/零提示/像素不变；真实新输入超过原 `.005` 门槛且可见，60 秒内 PNG 精确归位；默认光晕静止零请求、精确退场；明暗主题放大有必要提示且不挡输入；全屏初帧提示清除、Worker 释放；环境动画有连续完整帧且无重复提示；换图有正常反馈。此合同仅将已完成的真实 Worker bitmap 投递延迟 600ms，以确定性检验慢操作反馈，不改像素，不能作实际帧耗时证据。无延迟注入的初始修复探针，12 秒只出现进入后的 2 个收敛帧、0 次提示。

独立光晕算法合同的常规 30 帧与冻结 `59790af` 状态零差；每帧真实 Worker 收到相同手势，30 帧均激活，释放时仍有真实余波；1/2/5 秒间隔与原生小步进参考、同步/分段状态零差，事件回放零差。该部分用 alpha/coverage-zero fixture，仅证明算法。另用真实 48 列彩色字形验证断网 HTML，刻意将 rAF 调度间隔延迟 600ms，光晕可见且 PNG 精确恢复、零网络请求；不外推到高密度 HTML 性能。

两浏览器聚散数值回归通过；各 23 项 watchdog 故障合同包含合法光晕补算及经典光晕伪进度拒绝。Chrome 图片后台 80 项冻结 RGBA 零差，覆盖六模式、适用品质、透明度、Worker/兼容路径及取消、最新候选、全屏、缩放、回退。两浏览器完整视频回归包含 24 组冻结采样、18 组 Worker RGBA、六模式实播、暂停稳定、240 列 8 帧预解析与取消、全屏释放、390px 兼容回退。视频反馈合同覆盖两主题/两宽度、几何稳定和减少动效；真实 4 秒连续播放分别完成 4/6 个延迟投递的后台结果、生成提示零样本。

实际失败没有被最终通过覆盖：

1. UI R1 期待错误的 `current` 枚举，实际“流动”为 `wave`，修正测试；R2 捕获光晕 60 秒归位超时，上述真实时间修复解决，原门槛保持。
2. UI R3 前七项通过，但放大后的单帧超过固定 6 秒观察窗口，窗口中没有新请求，不能据此判定动画停止。最终合同等待至少两个真正更新了可见时间的完整帧，仍要求持续绘制、零提示；没有降低密度或画质。
3. 视频首轮捕获一个提示样本却未保存文字，保留其未确定原因。追加从明确起点开始且未到片尾的记录，再捕获一个样本，文字是“正在等待视频画面”，视频时间 1.762783、仍在播放。它属于浏览器媒体等待，不能当作重复生成。最终分别计数媒体等待与生成提示；真实等待继续显示，后续同素材两浏览器生成提示为零。模拟 waiting/canplay 的布局检查不证明所有网络 stall 已验收。

最终 type-check、相关 ESLint、生产 build 通过，既有 chunk、动态导入及 stream 警告保持。最终 UI/图片/视频/时钟报告包含实际源码或素材 hash；常规 v9 的 720 帧完整回归属于上一阶段，本次没有声称重跑。

## 限制与下一步

本阶段消除无用完整帧及错误生成提示，保留真实加载反馈；高密度单幅完整绘制依然可能耗时数秒，放大后更长。下一步继续研究完整静态帧和局部动态重绘，须先证明六模式、透明度和 RGBA 一致。本阶段没有接入缓存优化，也没有重启已停止的签名容量、视频 atlas、软件 tint/LUT 或 tile pool 调参。长视频、用户编码、真机、手写商业画质、原创内容与全部六方向目标继续；未部署、未宣布整体商业验收。
