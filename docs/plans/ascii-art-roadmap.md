# 图片转字符画 · 优化方向建议

> 面向当前 `/ascii-art` 能力：灰度字符、文字铺底、彩色预览、TXT/PNG 导出、主题自适应预览。  
> 原则：**先让「第一次就好看、愿意发出去」**，再做动态与后端。

---

## 1. 现状与定位

### 已具备

| 能力 | 说明 |
|------|------|
| 灰度字符 | 亮度映射字符集，多档清晰度（含极清） |
| 文字铺底 | 指定文案按明暗轮廓填充（如「我爱你中国」） |
| 彩色预览 | 按原图像素上色，两种模式通用 |
| 导出 | TXT（UTF-8 BOM、正向）、PNG（白底正向）；视频导出当前帧，或把选段编成 MP4 |
| 视频预览 | 标清/高清边播边算；超清/极清先出第一帧，选好选段再解析后播放（≤20 秒） |
| 视频导出 | 选段逐帧编码。≤480 帧可缓冲；更长边编码边丢帧；单次最多 3600 帧 |
| 预览体验 | 自适应缩放、Ctrl+滚轮、全屏（跟主题色）、主题正反向 |
| 悬停 / 微动 | 灰度字符模式可开 Studio 预览：拖尾、水面、丝绸、漩涡、等高、溶解；微动为慢流、重组、光斑。铺字模式不开 |
| 动效网页 | 「下载动效网页」导出可打开的 HTML：写入当前悬停/微动（都关时默认拖尾+慢流），字体与页面预览同为 Consolas |

### 建议产品定位

- **主记忆点**：中文铺字 + 彩色字符画（可晒、可表白），而不只是「又一个 ASCII 工具」。
- **信任点**：纯前端、图片/视频不上传服务器。
- **技术路线**：静态与动态预览先前端；服务端出片/存作品靠后。长视频导出用逐帧丢弃，不把字符帧整段留在内存里，也不把多个 MP4 再拼接。

## 1.1 当前视频方案（已定）

内存压力不在「边播边算」，而在「把每一帧字符和颜色都缓存下来」。预览和导出因此分开限制。

### 预览

| 清晰度 | 行为 |
|--------|------|
| 标清 / 高清 | 实时播放。每次只留当前帧，列数有实时上限。 |
| 超清 / 极清 | 上传后只渲染第一帧，不自动播放。用户选好入点/出点后点「解析并播放」，解析完才播。 |

- 解析播放只处理选段，最长 **20 秒**，缓存帧硬上限 **480**。这段要能拖动、循环，帧必须留在内存里。
- 长视频可以打开。默认选前 20 秒；用户用入点/出点改选段。播放到出点回到入点。
- 全屏背景跟随站点主题，不固定深色遮罩。

### 导出

| 格式 | 行为 |
|------|------|
| TXT / PNG | 当前帧。PNG 为白底正向，和预览主题无关。 |
| MP4 | 当前选段。WebCodecs（mediabunny）封装 H.264；浏览器不支持时再退回 MediaRecorder（常见为 WebM）。 |

- 内存预算 **480 帧**（15 fps 约 32 秒）。不超过就先攒齐再编码。
- 超过 480 帧：定位 → 转字符 → 写入同一个 MP4 → 丢掉这一帧，再读下一帧。内存大约始终只有当前帧加编码器缓冲。
- 单次硬上限 **3600 帧**（15 fps 约 4 分钟，24 fps 约 2.5 分钟）。再长请缩短选段或降低帧率。瓶颈是等待时间，不是把字符帧堆在内存里。
- **不做**「每 20 秒生成一个 MP4 再合并」。同一分辨率、同一编码下直接写入一个文件更简单，也避免浏览器无法直接拼接 MP4。

### 仍不做

- 服务端转码、云端存片、账号与广场。
- 为了互动预览而缓存超过 20 秒的超清字符帧。

## 2. 体验优化方向（P0）

目标：降低「不会用 / 调参慌 / 导出懵」三类摩擦。

### 2.1 首屏示范

- 提供 1–2 张内置示例图（人像、风景各一）。
- 「试试这张」一点即出效果，教会用户什么图适合。
- 空白态文案从「请上传」改为「上传或先试示例」。

### 2.2 风格预设（外露，高级内收）

在主操作区增加少量预设，一点改齐模式与关键参数，例如：

| 预设 | 意图 |
|------|------|
| 清晰单色 | 灰度 + 关彩色 + 高清 |
| 彩色 dens | 灰度 + 开彩色 + 高清/超清 |
| 告白铺字 | 文字铺底 + 默认文案 + 彩色 + 合适阈值 |

高级设置保留给深度用户；预设覆盖 80% 场景。

### 2.3 导出说明更清楚

- 下载旁固定提示：「导出为白底正向，记事本可直接打开」。
- 彩色开启时：PNG 标注「彩色图」；关闭时标注「单色字」。
- 避免用户误以为「预览深色 = 导出也是深色」。

### 2.4 重计算反馈

- 极清 + 彩色时显示明确「生成中」状态（按钮/预览区）。
- meta 可补充「已自适应缩至预览区」，减少「怎么这么小」的疑惑。

### 2.5 文字铺底引导

- 文案输入旁增加快捷芯片：表白、名字占位、节日等。
- 阈值/曝光与「铺满整图」用一句话解释结果差异（少字轮廓 vs 满屏字）。

### 2.6 已有交互保持

- Ctrl/⌘ + 滚轮缩放、全屏、恢复默认：保留并在首次使用时用短提示带过即可。

## 3. 产品能力方向

### 阶段 A · 静态打磨到「能晒」（优先）

- 完成第 2 节体验项。
- 可选：导出图带轻量品牌角标 / 分享构图（仍本地生成）。
- 成功标准：新用户 30 秒内能出一张愿意发朋友圈的图。

### 阶段 B · 动态字符视频（前端）

已落地：本地短视频选段、实时预览、超清先出第一帧再解析、MP4 逐帧导出（超内存预算则边编码边丢帧）。

仍可做、但不改变上面的内存方案：

- 摄像头实时字符预览。
- 导出等待时的取消与更细进度。
- **暂不做**：把长视频切成多段 MP4 再拼接；服务端高清转码。

成功标准：选一段能解析播放，更长的选段能导出成一个 MP4，且不会把全部字符帧留在内存里。

### 阶段 C · 传播与轻量沉淀

- 分享落地页或「复制分享文案」。
- 本地历史（IndexedDB）最近 N 次参数/缩略图，无账号。
- 水印/角标开关。

### 阶段 D · 后端（有明确需求再上）

仅在出现以下需求时启动：

- 长视频稳定到超过单次 3600 帧仍要一次出片（再评估是否上服务端，而不是浏览器里拼接 MP4）
- 作品云端保存与账号体系
- 公开广场 / 审核 / 运营配置

## 4. 差异化与叙事

| 要强调 | 少强调 |
|--------|--------|
| 用字画出图、表白/节日铺字 | 纯极客「ASCII 终端复古」单一叙事 |
| 本地处理、不上传 | 过早讲社区、积分、会员 |
| 彩色字符画观感 | 无限堆字符集却无预设 |

首页 / 工具页一句话示例：

> 本地图片转字符画：灰度或中文铺字，支持彩色预览，一键导出 TXT / PNG。

---

## 5. 建议不做或暂缓

- 同时大改静态体验 + 再上「分段 MP4 再合并」。导出已经用逐帧丢弃写入同一个文件。
- 无预设、无示例时继续加冷门参数。
- 一上来账号、广场、服务端存片。
- 与现有氛围站视觉冲突的「仪表盘式」控件堆叠。
