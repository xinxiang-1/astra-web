# 图片预览后台绘制与兼容恢复

延续[视频分段阶段](./video-render-slices-2026-10-05.md)。视频已经后台绘制，图片和全屏图片仍同步逐字绘制；高密度彩色中文会拖住参数、缩放和页面操作。本阶段解决执行位置、完整帧替换及失败恢复，不将页面响应等同于字符输出帧率。

## 实现

- 图片与全屏使用独立后台控制器，复用视频 Worker 和同一个 Canvas 工厂、真实字形、原 RGB、六模式及画质。每个目标最多一份正在绘制的任务、一份最新候选；真实指针样本按序合并，上限 128。后台临时彩色图块继续上限 64，没有接入被拒绝的 atlas 或软件着色方案。
- 参数、画质、尺寸或源帧变化会终止旧 Worker；动画时间与指针位置不参与配置身份，允许正在绘制的动态帧完成，避免永远没有画面。所有结果只在当前源、当前配置和可见页面上呈现。bitmap 用后关闭，源替换、卸载、全屏关闭及画布替换释放对应控制器。
- Worker 不可用或失败时，在独立 GPU staging Canvas 分段绘制。共享 `renderResponsive` 增加取消检查，每次继续 generator 前检查；取消后销毁旧 renderer，再画最新候选。图片与视频兼容路径均不向可见 Canvas 写半帧。8ms 是时间片检查预算，单次 Canvas/GPU 调用仍无法中途打断。
- 上一幅完整画面保留，150ms 后显示共享双主题进度浮层，全屏显示百分比。多个目标的忙碌状态统一计算，关闭全屏不误清除主预览反馈。兼容说明也使用浮层，避免成为预览 grid 的第三行。
- Worker 返回实际完成的缓存/粒子状态；回调携带实际发送的参数，Canvas 元数据记录该帧的时间、指针强度及效果，不能用最新全局参数标注旧画面。图像采样仍在主线程响应式执行；没有把整条管线称为完全后台。

签名方向引导、常用功能分类、共享主题控件沿用[已有工作台](./signature-theme-workspace-2026-10-04.md)与[方向阶段](./signature-direction-2026-10-04.md)，本阶段未改签名排版。首页三保护源、Studio `.65/.38/.45`、用户认可的 FxButton、PNG/TXT/视频/HTML 的免费边界保持。

## 拒绝的实验及实际修复

1. GPU 校准颜色/alpha 查找表先在局部场景零差，扩大到 CPU 目标后失败：Consolas“我”、黑色、缩放 .17、透明度 .37、偏移 .27，13 通道变化，最大差 6。180×191 彩色中文整画的 CPU Canvas 和 ImageBitmap 两条路径均有 561161 通道变化，最大差 178，首帧约 7 秒。抽查 300 个原生图块本身 1:1 RGBA 相同，整画差异的具体原因尚未证明。拒绝接入；原实验脚本 exit 0 不代表报告的 `passed:false` 通过。
2. 128 个独立原生图块分批着色：三帧 RGBA 零差，但耗时 11.543 / 15.427 / 13.247 秒，对照为 21.019 / 8.477 / 7.692 秒。后续更慢，拒绝接入，不继续调 pool 大小。这些耗时不能直接与本阶段不同负载/浏览器状态的新测量当作加速比。
3. 首轮类型检查发现三个同步导出/项目预览位置仍需 Canvas 工厂，恢复 import；同步输出接口继续保留。
4. 重场景 QA 第一帧原生粒子能量就是零，错误要求三帧全部大于 .005；三帧像素实际上相同。改为逐帧与原生 peak 精确比较，最后一帧必须有可见能量。该轮 rAF 采样还混入同步参考绘制的阻塞，修正为先完成参考、隔两帧再测 Worker，不将参考阶段计入后台响应。原失败报告保留，未改产品求解器或像素门槛。

## 验证与限制

证据归档在[图片后台验证目录](../validation/2026-10-05/image-preview-background/)，每份报告保留实际浏览器版本和源码范围。

- Chrome / Edge 各 80 项：六模式，密度精细/柔和/还原及原色还原，透明/不透明、light/particles，Worker/分段兼容。与冻结 `5adb64a` Canvas RGBA 零差；实际参数、交互活动和粒子容量相同。
- 两浏览器验证过期尺寸终止、旧 bitmap 忽略/关闭、动画不会使结果饿死、只发送最新候选、128 样本顺序、取消保留旧完整画面、兼容源替换、运行错误回退、全屏 2→1 控制器释放、真实放大、390px 构造失败回退。
- Chrome 实际页面 180×191、571×713 静态彩色中文：后台约 2.409 秒，主题按钮 80ms 响应，20ms timer 最大 42.6ms，页面 rAF P95 50ms/最大 66.7ms，最终原生 RGBA 零差。测试直接设置开发页面的已准备帧；不冒充整段用户上传、准备、交互的端到端延迟。
- Chrome 同尺寸三帧聚散：后台约 2.158 / 2.219 / 2.210 秒，timer 最大约 21.7ms，RGBA 与每帧粒子 peak 都相同；最后 peak .02054，粒子 2.75MiB。第一帧原生初始化为零。参考先绘制会影响缓存和 GPU 状态，不能外推稳定提速倍数或 60fps。
- Chrome 生产构建用真实上传、按钮和鼠标完成六模式 80 列后台预览；聚散有可见变化、离开后约 10.466 秒精确归位，全屏 Worker 2→1，缩放、主题及离开页面释放通过。原报告 scope 误写“64-column”，实际 `modes[].columns` 均为 80；脚本随后改为不写固定列数，原报告保留。没有借此称 180 列归位已通过。
- Edge / Chrome 完整视频回归：24 组冻结采样、18 组冻结 Worker RGBA 零差，六模式实播、暂停稳定、240 列 8 帧预解析/取消、全屏释放、390px 及分段兼容回退通过。Edge 容量合同确认编辑器/HTML 允许滚动且输入零重绘，Chrome 九项 watchdog 虚拟故障通过。最终 type-check、相关 ESLint、build 通过，既有大块、动态导入和 stream 外部化构建警告保留。真实视频仍只验证本地短 fixture，buffering 是事件替身，不证明网络 stall、长视频和任意用户编码均不卡。

重场景每帧仍以秒计，主线程让出后并未达到实时交互速度。`.15/.25` 时钟步长限制与真实归位时间仍待独立优化；此前生产 Chrome 60 秒归位失败没有凭本阶段三帧或虚拟时钟消除。低端设备、长视频、真手写商业审美和整体六方向商业验收继续进行。未部署，未标记整体目标完成。
