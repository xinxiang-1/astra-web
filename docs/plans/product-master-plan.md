## 1. 项目方向与执行原则

### 1.1 一句话定位

**Astra 是一个将图片、短视频和文字转成可发布艺术作品的本地优先创作工具，同时提供可嵌入网站的实时视觉与定制服务。**

首页主张建议：「把照片，变成由文字组成的作品。」

核心用户依次为：

1. 内容创作者、摄影爱好者：人像、封面、短视频、社交媒体配图。
2. 有纪念与表达需求的普通用户：告白、名字、节日、纪念照片。
3. 设计师、独立开发者与品牌客户：海报模板、网页视觉、活动页与特效定制。

先验证中文用户和中文铺字差异化。英文市场作为后续扩展；首版不承担完整双语运营成本。

### 1.2 产品主线

- 创作工具负责让用户完成作品，是长期产品基础。
- 精选案例和模板负责展示效果、指导创作、带来搜索与传播流量。
- 视觉工作室负责展示 Prism、黑洞、流体等能力，形成定制服务收入。
- 账户、订单与权益负责支撑真实交易；云同步按需求后置。
- 文件预览、签名画像、动态字符和循环嵌入作为辅助或实验能力，不抢占首页主行动。

### 1.3 约束

- 小步交付，每阶段有成果文件、演示入口、验收标准和完成记录。
- 每完成一个可验收小阶段，更新工程文档、记录失败与验证，单独提交并立即推送；使用GitHub MCP配置的xinxiang-1账户，核验远端SHA后报告成功。
- 先确定效果与用户流程，再细化需求、API、数据库和实现。
- 保留已有图像转换、视频导出、本地项目与特效引擎，按模块重构。
- 所有新增收益、价格、工期和转化率都是待验证假设。
- 免费体验无需登录；有账户价值或购买行为时再引导登录。
- 当前已有免费导出继续保留，付费来自新增便利、模板内容、服务与后续云能力。
- 对用户展示真实状态：模板示例、实验功能、本地项目和未上线功能都要说明准确。

## 3. 网站统一风格与内容

### 3.1 视觉方向

建议沿用最近画廊原型：**现代艺术画廊 × 精密创作工具 × 克制的实时视觉。**

- 主色：石墨黑 `#151918`、暖纸白 `#f5f3ef`、青色 `#58e8ed`，沿用当前 art tokens。
- 首页和工作室以暗色衬托作品，案例与说明区可采用纸白；编辑器保持稳定、清晰的操作面板。
- 标题使用当前衬线体系，正文采用易读无衬线，参数和辅助标记用等宽字体；中文字体加载和回落需验证。
- 全站统一品牌字标、字号等级、间距、图标、按钮、抽屉、表单、消息和状态表现。
- 用作品、排版和留白建立气势，青色强调主要操作，避免每个区块都竞争注意力。
- 产品内容优先中文；英文只用于少量品牌辅助信息，重要提示不能依赖英文小字。
- 暂不增加两套独立设计系统。原型阶段确定哪些页面固定主题、哪些支持切换，再形成统一 token 映射。

### 3.2 大气特效的落地规则

1. 首页主视觉仍是实际字符作品：原图对比、字符聚合、轻微空间移动；让用户立即理解产品。
2. Prism 作为工作室核心展示，可用于局部视觉过渡；默认不与首页全屏字符画同时持续运行。
3. 工作室允许完整沉浸式特效；账户、订单、帮助等页面采用轻量背景。
4. 控件交互建议 120–220 ms，区块入场 300–600 ms；不劫持滚动、不长期遮住按钮。
5. 页面不可见、画布离屏或路由离开时暂停渲染，并释放资源。
6. WebGPU 不可用时按特效能力回落到 WebGL、录制视频或静态海报，不显示黑屏。
7. 尊重 `prefers-reduced-motion`；移动端默认降低分辨率、粒子和采样，不把所有设备强行拉到最高画质。
8. 原型验收既看首屏截图，也看实际运行、交互和降级效果。

### 3.3 内容规则

- 主 CTA 统一「免费制作」；示例 CTA「使用这个风格」；服务 CTA「咨询定制」。
- `/gallery` 优先命名「风格案例」或「精选案例」，描述模板如何产生效果。
- 统一称「视觉工作室」，避免同一模块交替叫实验室、Studio、作品集。
- 只有确实本地处理的流程才显示「无需上传」；将来用户主动云同步时单独说明上传范围。
- 不显示虚构用户数量、好评、成功支付、导出次数或订阅权益。
- 商用许可限定于有权提供的模板、资产和服务；用户上传素材仍需自行拥有使用权。

## 4. 信息架构与前端功能计划

### 4.1 用户旅程

访客看到真实效果 → 尝试示例或上传 → 选择风格和文字 → 预览调节 → 免费导出 → 保存本地项目或下载备份 → 按需购买新模板/咨询定制 → 后续复访。

任何登录、购买或失败恢复流程，都应尽量保留用户当前作品和参数。

### 4.2 页面与模块

**首页 `/`：** 一句话价值、可操作的原图/结果对比、代表风格、三步创作、格式和隐私说明、工作室服务入口、统一页脚。首次访客应在 5 秒内理解主产品。

**案例 `/gallery`：** 分类和搜索、静态/动态标识、适用素材说明、使用预设进入编辑器。首版不做用户上传广场、点赞排行和审核系统。

**编辑器 `/ascii-art`：** 桌面源素材/预设、中心预览、参数三区；移动端预览在前，底部标签和导出按钮。基本参数优先，高级参数折叠。

- 上传前展示建议格式、尺寸、视频时长；依据现有引擎实测制定限制。
- 支持示例、预设、文字、颜色、缩放、对比和全屏；新增撤销/恢复能力前先确定历史粒度与性能预算。
- 明确计算、导出、取消、失败和重试状态；快速调参时旧计算不得覆盖最新结果。
- 导出说明文件格式、尺寸、背景、兼容性与预计耗时；预览与导出使用一致的字形、色板和比例。
- 高负载视频使用已有分帧策略，验证 Web Worker 或现有工作线程适用性，再决定优化方式。

**导出抽屉：** 保留现有免费格式；付费模板与后续功能明确展示差异。购买后回到原作品。动态 HTML 标明联网依赖；自包含离线包作为待评估新增能力。

**项目 `/projects`：** 维持本地保存、打开、搜索、筛选和删除；增加项目备份/恢复候选方案、配额与存储错误提示。标注「本机项目」，以后再提供单独「云项目」。

**视觉工作室 `/studio` 及特效路由：** 特效缩略展示、进入沉浸体验、使用场景、嵌入说明、兼容性、性能档位、定制服务范围。多个预览同屏时限制活跃渲染数量。

**账户 `/login` 等：** 统一视觉，优先密码/邮箱。登录后增加账户信息、订单与权益页；真实微信/短信未接入前隐藏生产入口。

**新增 `/pricing`：** 只在有真实商品或服务后发布；清晰展示一次性购买、有效期、支持范围、退款规则，订阅后置。

**新增 `/help`、`/privacy`、`/terms`、`/contact`：** 上传与导出问题、浏览器限制、数据保存规则、购买协议、服务咨询；首版可用静态内容。

**新增 `/admin`：** 后期管理商品、订单、退款和咨询，不应直接照搬完整企业后台。管理员权限必须由服务端强制校验。

### 4.3 前端结构建议

保留 Vue 栈。逐步整理为 app 页面壳、共享 UI、design tokens、features/art、features/projects、features/account、features/commerce、features/studio；现有 `lib/ascii` 与 `effects` 保持引擎边界。目录迁移在具体模块迭代中完成。

- 全站导航和模块说明使用共享内容来源，减少多份文案漂移。
- 区分本地状态、账户状态、服务端权益；本地项目不以登录状态为前提。
- API 层统一超时、错误码、重试范围、401 处理和请求追踪；金额订单不能随意自动重试。
- 重特效、文件预览和编辑器按路由/功能懒加载，验证包体和首屏改善。
- 无障碍覆盖键盘、焦点、标签、状态播报、对比度和 44 px 触控目标。
- 搜索入口页后续评估预渲染或 SSR；编辑器维持客户端计算。不要仅为了 SEO 全面更换技术栈。

## 5. 后端完整演进计划

### 5.1 架构选择

沿用现有 gateway + auth + system。首期在 system 中按业务包分离商品、订单、权益和咨询，不新增多个独立微服务。复杂度或负载证明有需要时再拆。

请求链路：浏览器 → HTTPS 反向代理 → gateway → auth / system → MySQL、Redis。对象存储只在云资产、项目同步或服务交付确有需要时引入。

浏览器负责当前字符转换与媒体导出。后端负责可信的账户、交易、资产访问与业务规则。首版不建设 GPU 集群、云视频转码和任务编排平台。

### 5.2 分模块交付

**认证：** 核实邮箱发码、密码重置、注销/登出、验证码限流、密码哈希、Token 失效和跨端行为；梳理 localStorage Token、XSS 与会话策略，形成明确设计。生产禁止 mock 验证渠道。

**商品与模板：** SKU、版本、上下架、价格、模板资产、授权范围和历史购买记录；付费资产通过服务端权益校验后下载，不提前放入公开包。

**订单与支付：** 服务端生成订单与价格快照，接入一个获准使用的支付渠道，处理支付确认、超时关闭、退款和对账。

**权益：** 将购买商品映射到模板版本或服务权限；有效期、冻结、退款撤销都可审计。订阅和用量额度仅在确有需要时引入。

**咨询与交付：** 收集用途、预算区间、期限和联系渠道；后台记录咨询、报价、成交与交付状态。联系资料不进入公开页面。

**云项目（后置）：** 用户主动启用，明确源文件是否上传、容量、冲突策略、删除与导出；通过项目所有权和对象权限校验。

**运营后台：** 商品与案例配置、订单搜索、退款处理、咨询记录、操作审计；先满足真实运营场景。

### 5.3 数据模型草案

沿用现有认证表，新增业务实体建议：

- `product` / `product_sku`：商品、版本、币种、最小货币单位金额、上下架状态。
- `template` / `asset`：模板配置、资产归属、校验和、许可文本版本、存储位置。
- `order` / `order_item`：用户、金额快照、状态、到期时间、商品与许可快照。
- `payment` / `payment_event`：渠道流水、回调唯一标识、验签结果、处理状态。
- `refund`：金额、申请原因、渠道退款号、状态和处理记录。
- `entitlement`：用户、权益类型、来源订单、有效期、撤销信息。
- `studio_lead`：需求摘要、联系资料、咨询状态和保留期限。
- `admin_audit_log`：操作人、动作、目标、时间和审计信息。
- `cloud_project` / `project_version`：仅云同步阶段引入。

数据库文档阶段确定字段、索引、唯一约束、事务边界和迁移方案；此处不是可直接执行的建表脚本。订单删除不得抹掉对账与退款证据，个人资料删除和交易留存规则单独设计。

### 5.4 API 分组草案

- 保留 `/api/auth/**`。
- 沿用网关业务前缀，新增 `/api/system/catalog/**`、`/orders/**`、`/entitlements/**`、`/assets/**`、`/leads/**`、`/admin/**`。
- 支付回调设独立允许通行路径，但必须验签，不能仅依赖 JWT。
- 云同步阶段新增 `/api/system/projects/**`。

正式接口文档要逐项描述字段、示例、身份、授权、幂等键、错误码、分页、状态码和客户端恢复方式；金额由服务端定义，不相信客户端传入的价格。

### 5.5 支付最小正确性

1. 订单状态建议：待支付 → 已支付 / 已关闭；退款单独记录处理中、成功与失败。
2. 回调验签并验证商户、渠道、币种、金额、订单对应关系；浏览器跳转不作为付款证据。
3. 渠道事件和订单迁移具备唯一约束与幂等；重复、延迟、乱序回调不能重复授予权益。
4. 支付成功、权益写入使用数据库事务；外部动作通过可重试记录/补偿完成。
5. 定时查询未决交易、处理超时订单和日常对账；保留人工修复入口及审计。
6. 退款撤销相应权益；已下载资产无法收回，这一点需要体现在数字商品退款政策。
7. 付费功能完全在浏览器执行时不能做到可靠防绕过。模板服务、更新支持和交付价值才是首期付费基础；不依赖前端按钮锁定产生收入。

## 6. 赚钱策略与验证方法

### 6.1 先做两条可以交付的收入线

**收入线 A：模板与创作素材包。** 售卖精心制作的风格、中文排版、配色、节日/海报构图、可编辑配置和使用指南；基础转换与现有导出继续免费。候选测试价格：单主题包 ¥19–39，综合包 ¥59–99。付费前展示完整样张和可交付清单。

**收入线 B：视觉工作室定制。** 用 Prism、黑洞、流体案例展示真实能力；提供网页首屏特效、活动视觉、品牌氛围背景与嵌入适配。候选报价：标准化单特效适配 ¥1,500–5,000，复杂定制单独评估。报价必须写设备范围、修改轮数、部署责任、源码/许可、维护期和里程碑款项。

以上为报价实验，不是市场行情结论。首个模板包或服务报价只有在资产许可、交付内容和履约能力明确后才发布。

### 6.2 再评估 Pro

首版候选新增价值：批量处理、批量尺寸版式、经过授权的私有排版内容及更新支持，具体范围见[商业PRD](./prd-commerce.md)。现有个人预设和可移植.astra作品包备份保持免费，不能再当新增Pro卖点；云同步和托管嵌入必须另算成本。

- 先测试一次性功能/内容包，再判断复购和持续使用是否支持订阅。
- 若确有持续价值，可测试 ¥29–49/月；年费须明确维护承诺和退款条件。
- 不能把当前免费的 4K、透明 PNG、TXT、视频或 HTML 改写成「已实现的会员专属」。
- 不将「商用权」笼统当成收费开关；只对自己有权许可的模板与资产授予约定权利。
- 不优先依赖展示广告、无限流量云渲染或低价终身无限服务。

### 6.3 收入与成本模型

按月记录：商品收入 + 定制服务收入 − 支付手续费 − 退款 − 服务器/存储/邮件 − 推广 − 外包与素材 − 人工成本。

演示假设：5,000 个合格访客 × 20% 开始创作 × 50% 成功导出 = 500 个成功创作者；其中 3% 购买 ¥39 模板包 = ¥585。另有 2 单 × ¥2,000 定制 = ¥4,000，总营收 ¥4,585。

若基础设施假设 ¥500、手续费按 1% 简化计算、退款预留按模板收入 5% 计算，剩余约 ¥4,009.90；**尚未扣人工、推广、税费和外包，不能称为净利润。** 所有数字只是展示计算方法，不是预测。两种收入分别归因，服务收入不能证明模板付费模式成立。

对 ¥39 模板包，假定手续费 1%、退款预留 5%、可变成本 ¥1，单笔贡献约 ¥35.66；仅覆盖 ¥500 固定现金成本约需 15 笔。若额外计入 ¥6,000 人工，则约需 183 笔；需用真实费用替换。

基础预算起点：免费前端公测 ¥0–200/月；保留当前 Java 服务、Nacos、数据库与 Redis 的小流量完整环境按 ¥300–1,000/月做选型预算，域名和一次性成本另算。不是供应商报价，需按内存实测、地区、冗余和流量确认。

### 6.4 获取第一批用户

- 先做 6–12 个有代表性的实际案例，注明素材来源与制作参数。
- 发布人像、中文告白、节日海报、动态字符制作教程；优先选择一个内容平台持续测试。
- 搜索主题围绕「图片转字符画」「中文文字肖像」「字符视频」，每个入口给示例和创作按钮。
- 工具结果页提供用户自愿使用的分享文案与品牌署名，不默认公开原图。
- 工作室页面展示用途、支持范围和可联系渠道，手动跟踪咨询到成交。
- 首批邀请 10–20 人完成任务访谈，记录卡点；再做 30–50 人小范围公测。

### 6.5 指标与决策

事件建议：示例试用、上传成功、预设应用、首张预览完成、导出开始/成功/失败、本地保存、商品详情、订单创建、支付成功、咨询提交。分析不采集原图、视频内容或用户自定义文字，公开说明必要分析信息。

- 主指标：成功导出的创作者数和有效付费/咨询数。
- 漏斗：访问 → 开始创作 → 成功预览 → 成功导出 → 购买/咨询。
- 首轮目标假设：10–20 次任务测试中至少 80% 不经口头指导完成样例图导出；如不达标先修体验。
- 商品试验：争取 3–5 笔真实模板订单或 1 笔真实服务成交，再考虑扩大范围；这只证明初步意愿。
- 分别记录 7 日/30 日回访、复购、退款原因、客服工时和单笔贡献。
- 曝光或样本不足时不能断言需求不成立；有曝光无创作先修定位，有创作无导出先修体验，有导出无付费再检查商品价值。

## 10. 测试与性能标准

### 10.1 必须验证的场景

- 正常图片、透明 PNG、大图、损坏/不支持文件和连续快速调参。
- 短视频选段、导出进度与取消、内存约束、编码不支持和失败重试。
- PNG 尺寸/透明度、TXT 内容、视频播放与 HTML 图片/视频依赖。
- 预览和导出色板、字形、布局一致；样例含中文、人像、风景和高频纹理。
- 本地保存、重开、删除取消、存储不足、源文件恢复和浏览器数据清理提示。
- 登录失败、邮箱限流、会话过期、回到原作品；生产禁用 mock。
- 订单金额、未付款拒绝访问、重复回调、退款撤权、管理员与普通用户越权。
- 深链接、移动菜单、键盘焦点、触控、页面离开资源释放、WebGPU 不支持与减少动效。

### 10.2 初始性能预算

以下为目标，不是已测结果；S0 记录设备和样例，S3 按同一条件验收：

- 面向内容页：真实用户 p75 LCP ≤ 2.5 秒、INP ≤ 200 ms、CLS ≤ 0.1；首期实验室数据作为参考，积累足够真实流量后再判定。
- 1920×1080、DPR 1 的选定中档桌面设备：核心展示争取 60 fps；移动设备稳定 30 fps 或主动降级，记录实际设备/GPU和质量档。
- 固定 2048 px 长边样例：在选定桌面设备上初次字符预览目标 ≤ 3 秒；高质量计算持续时需有反馈并保持主要操作可用。
- 长任务可取消；控制视频帧数和缓存预算；切换路由后不能继续保持无用动画与媒体对象。
- 首页不预载所有引擎和 Office 预览资源；在性能记录中报告 JS、字体、图片的实际下载体积。

### 10.3 检查方式

沿用 `art-ui-smoke.mjs`、`art-export-smoke.mjs`、`test:ascii-consistency` 并按改动选择必要覆盖。直接执行 `vue-tsc --noEmit -p tsconfig.views.json` 判断真实类型结果，不能以目前软成功脚本作为通过证据。

后端新增有意义的认证、状态机、幂等与授权测试；运行 Maven 对应模块测试与打包。涉及 MySQL/Redis 的集成检查使用一致配置。把构建、类型和关键回归纳入 CI，失败阻断发布。

## 11. 部署与运行计划

### 11.1 首次部署

- 前端静态产物可部署到支持自定义域名、HTTPS 和 SPA 回退的静态平台；API 使用独立受控 Java 环境。
- 小规模完整后端可先采用单台 Linux 主机运行当前服务和基础设施，实测内存；这是单点结构，需明确可用性限制和恢复办法。
- Nginx/Caddy 将业务域名下 `/api` 转到 gateway，前端历史路由回退到 `index.html`；静态文件不存在不能被错误回退。
- Nacos、MySQL、Redis 与内部服务端口限内网访问，公网仅开放所需 HTTP/HTTPS 管理入口。
- 初期只开已验证的生产登录渠道，不依赖本机 Windows 路径与开发默认密码。

### 11.2 环境与发布

区分 local、staging、production，隔离数据库、邮件、商户和密钥；配置由环境变量或安全配置注入。JWT 密钥、SMTP 授权码和支付证书不提交源码。

CI：安装锁定依赖 → 严格类型检查 → 相关 lint/测试 → 前端构建与 JDK 21 Maven 打包 → 生成有版本的产物 → 部署 staging → 验证 → 发布生产。数据库采用版本化迁移，先兼容旧版本再上线新代码。

保存上一版本产物，定义应用回滚和数据库前向修复策略；不要假设数据库迁移都可逆。记录版本号、配置版本、迁移号和发布日期。

### 11.3 可观测性与恢复

- 网关、认证、业务日志带 trace ID，避免记录密码、Token 和原始素材。
- 监控可用性、5xx、API 延迟、邮件失败、支付回调失败、待决订单、磁盘和 JVM 内存。
- 对不可用、支付不一致、备份失败等可行动事件告警。
- MySQL 每日备份至独立位置，初始保留 7–30 天；对象资产和配置按引入范围备份。
- 初始恢复目标假设 RPO ≤ 24 小时、RTO ≤ 4 小时，需实际演练证明，不能当成对用户保证。
- 商业支付阶段提高订单恢复能力，结合数据库日志/时间点恢复与支付渠道对账，尽量将交易 RPO 降至分钟级。

### 11.4 上线清单

域名与证书；深链接；真实邮件；关闭 mock；独立密钥与最小权限；商品许可；支付/退款；隐私/条款/联系方式；浏览器兼容；错误告警；数据备份与恢复；发布回滚。

部署地区在 S0 确定：大陆节点评估备案、域名和运营主体要求；境外节点实测国内用户访问、邮件与支付可用性。支付渠道能力以商户资格和实际开通结果为准。

## 12. 风险、待决问题与后续协作

### 12.1 主要风险与应对

- 视觉越来越复杂但创作完成率没有提高：每次特效迭代同时检查可读性、转化和性能。

- 账户/支付上线但无运营售后：先有可交付商品、退款规则和责任人再开放购买。
- 个人精力被微服务、社区与渲染平台分散：沿用当前服务边界，逐项验证再扩展。
