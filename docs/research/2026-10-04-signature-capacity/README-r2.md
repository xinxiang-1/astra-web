# 高分辨率完整笔迹拼贴 · R2

实现前登记 [experiment-r2.json](./experiment-r2.json)，继承 [R1 来源与算法](./README.md)，这是本假设的最后一轮。[v11 原型](../../prototypes/v11-signature-print/index.html) 可切换 2K/4K、两图、三模板集、两底色与三个算法；仅独立研究，尚未晋升。

## 改变与公平范围

输出最长边 2048 / 4096，候选完整笔迹原生高度≥16px；分析最长边保持≤1024。不是将旧成品拉伸：在真实输出的整数坐标中重新划分，按最终尺寸测量完整签名容量，绘制新布局。原图仍只参与统计，最终重放只接收 scene 和模板。

所有对照使用相同源图、输出尺寸、底色和 seed。生产 woven 的原参数（density 30、minSizeRatio .014、maxSizeRatio .04、angleRange 12）保持，因此它的字样随画幅等比放大；候选使用固定原生最小高度，会增加字数。**这不是字数、签名尺寸或算法参数完全相同的消融实验。** 2K/4K 下都按同一冻结面积评价器计算，阈值未放宽；没有照片色阶重映射。

历史矢量重绘与字体辅助仍不能代表私人真人手写。源图来自已有本地生成素材，没有新增原生4K摄影细节；未使用 Darwin / Curie 最终来源。

## 跨分辨率积分

分析像素视为分片常数。整数 summed-area 的连续扩展 `S(x,y)` 用四角双线性插值：这是像素常数区域的精确积分，不是对照片重新生成笔迹。输出格的两端映射到分析坐标后，面积积分为 `S(x1,y1)-S(x0,y1)-S(x1,y0)+S(x0,y0)`，除以分析区域面积得到目标平均墨量；平方积分同理算方差。

独立参考按每个原像素与矩形实际相交面积累加，覆盖200个非整数矩形与边界。分区完整性另用最终尺寸逐像素占用数组检查，不仅检查自身矩形逻辑。源图不参与画面重放，也不作为逐像素 alpha。

预算保持积分数组24MiB、模板RGBA16MiB；输出最大16,777,216像素，单个输出RGBA≤64MiB，审计占用数组≤16MiB，最多64,000格。源画布、PNG解码、评价数组、浏览器/GPU和并存输出另占内存；这些上限不能称为总内存认证。

## 复现与判定

先启动开发服务，运行 `npm run research:signature-print`（72组），然后 `npm run test:signature-print-ui`。`ASTRA_PRINT_OUTPUT` 指定开发输出目录；UI 使用 `ASTRA_PRINT_DATA` 读取同一目录。可指定 `ASTRA_BROWSER_CHANNEL=msedge` 或 `chrome`，不依赖缺失的 bundled Chromium。

`node scripts/signature-print-evidence.mjs` 从冻结PNG生成三幅对比板，完整图按同大小缩放，280×180裁片按1:1展示并核对201600通道；不把对比板当原始4K成品。`ASTRA_R1_DATA` / `ASTRA_PRINT_DATA` / `ASTRA_PRINT_EVIDENCE` 指定输入/输出目录。

完整管线计时包含分区、模板着色、绘制和整幅同步RGBA读回，排除字体生成/UI/PNG/审计；1冷+1预热+7重复。初次开发序列早段与 type-check/build、一次概览提取有重叠，因此保留其原记录。独立计时审计脚本 `node scripts/signature-print-timing.mjs` 已准备但本阶段未执行：用户随后明确优先解决生产页面卡顿，独立计时留作后续工具，不能声称已经独立认证。不会挑最低数字，也不与不同模板/尺寸的生产基线宣称加速。

最终指标、实际图片审查与停止决定见 [阶段记录](../../plans/signature-print-iteration-2026-10-04.md) 和 [冻结证据](../../validation/2026-10-04/signature-print/README.md)。16px是在此栅格中的笔迹高度；在300dpi印刷中仅约1.35mm，不能自动证明每个字母/汉字可读。4K会让格子在概览中变小，不能消除负笔迹墨版的结构性阶梯。两轮后停止本假设的继续调参，真实纯手写、自然笔迹、印刷与通用商业画质仍须单独解决。
