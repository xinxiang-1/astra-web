## 3. 原理拆解与复刻合同

### 位移、流体与撕裂

一般位移贴图把通道值映射为 `d = A(2m−1)`，再采样 `I(x+d)`。字符作品应移动原来的字格与字形，而不是只扭曲一张照片。为了不把中文翻转，持续织物形变需要检查局部 Jacobian `det(I+∇d)>0`；粒子聚散允许字格位置交叉，但字形本身仍保持正向，恢复后的句序不变。

流体的基本分工是速度注入、平流、扩散/阻尼、涡量细节和压力投影。Astra 已移植原生求解器；`sampleFluidField` 给出 UV/秒速度和 UV 位移，二者不能互换。撕裂响应应由速度、密度梯度及有界形变消费这份场，后续 CPU/GPU 复刻也必须保持相同单位和输入时钟。

### 当前字符粒子候选

入口：[v9 可操作对照](../../prototypes/v9-glyph-particles/index.html)。模块 [presentation.ts](../../prototypes/v9-glyph-particles/presentation.ts) 通过现有 `experimentalTrail` 回调消费场，没有修改共享 Canvas 工厂或正式 hover 白名单。

每个字格保留两维位置偏移 q 与速度 v；固定字格编号产生确定的散开方向、幅度和回复频率。将 UV 速度换算到画面短边单位后，能量为 `E=clamp(3.4|u|+0.18ρ,0,1)`。目标位移由速度方向、固定角度扰动、原生位移和用户强度构成；单轴目标最大短边的 0.18。它是持续力的目标，不是逐帧累加一团随机噪声。

对每一轴使用 `q''+2ζωq'+ω²(q−T)=0`，ζ=0.76、ω=8～12。对一帧内固定的 T 使用闭式步进：

`r=q−T, a=ζω, b=ω√(1−ζ²)`

`q_next=T+exp(−aΔt)[r cos(bΔt)+(v+ar)sin(bΔt)/b]`

`v_next=exp(−aΔt)[v cos(bΔt)−(av+ω²r)sin(bΔt)/b]`

它避免显式 Euler 在长帧下爆炸；30/60Hz 的恒定力实验另外核对误差。它不代表任意变化力或原生求解器在所有帧率下完全相同。单帧有效时间上限 0.25 秒，与原生场追帧上限一致。

局部细节来自原字符强度与透明度，字形不旋转、不镜像、不换成圆点。小幅滤镜光晕曾使透明面积输出归位后出现 RGB 1 级差异，已从此候选移除；保留实际字符内的亮度反馈，未放宽精确恢复检查。状态预算 4 MiB，112 列瓷像当前约 245 KiB；超过预算明确拒绝，不偷偷降低列数。正式项目 / `.astra` / 离线动态 HTML / 交互视频尚未接入。

### 波纹、扫描、故障与噪声

波前可用 `w=exp(−λt)exp(−(r−ct)²/σ²)` 形成窄环；位移沿局部法线，亮度只乘原字形遮罩。触点事件应保留连续路径，不能每帧重新生成互不相连的圆点。多个波前必须有数量和寿命上限。

扫描用方向投影 `s=n·x−vt` 决定窄束/显隐范围，周期边界要光滑；全息表现可增加有界深度与字符内光线，避免全幅闪白。RGB 分离只对有颜色的真实字形分别施加短时偏移；行带噪声须固定种子、限定脉冲与恢复时刻，不能把持续文字抖动作为默认效果。

二维 Curl 场可写 `u=(∂ψ/∂y,−∂ψ/∂x)`，无散性适合流动轨迹；若另造独立流场会失去现有手感与输出一致性，优先从共享场派生。扫描、噪声、粒子入场用于视频时需使用输出时间，不能依赖墙钟或不可重播的 Math.random。

## 4. 多方向玩法迭代

1. 内容创作：短视频循环封面、横竖屏安全区、电影海报、音乐节视觉；先验证实际 MP4/WebM 编解码、周期接缝与慢设备取消。
2. 中文表达：告白 / 家庭 / 纪念句序、长短名字、标点和中英混排；清晰字符组成画面，手机先保住人物轮廓。
3. 交互网页：悬停 / 点击冲击、可嵌入离线作品、主题与作品参数一致；触控必须有显式释放和减少动效回退。
4. 印刷：纯字符 / 原色 / 黑白 / 透明；重算真实 4K 布局，检查细线、局部原大和 SVG 边缘。高分辨率 PNG 不等于矢量印刷通过。
5. 名字画：真实手写与字体辅助两条来源，细 / 中 / 丰富墨量预设，双人签名与纪念日期组合；先解决墨量容量、重复结构、可读性与完整恢复。
6. 商业交付：原创素材 + 经过验证的效果 + 可恢复模板说明；免费已有输出继续保留。模板付费来自内容与新增创作便利，不把外部图库原图直接打包收费。

## 5. 名字画的关键瓶颈

当前 `woven` 将整段签名放入矩形区域，槽位墨量能力由 `C=inkRatio·stampArea·scale²/slotArea` 决定，且透明度≤1。目标暗度远大于 C 时，多调透明度或换噪声不能凭空产生墨迹。放大薄签名也不能提高其相对墨量。这解释了前次实验的暗部不足，以及墨版提高对比度却产生砖块观感。

本轮 `creative-baseline-audit.mjs` 实际测量现有自动字体写法的 alpha 覆盖率、长宽比、woven 几何容量，并审计主站。它是研发诊断，不是新的真实手写训练集或商业画质评分。下一轮按结果选择以下路径，而非给前次已停止实验追加调参：

- 真实手写：保留指针笔压与完整笔画，形成可直接缩放的路径模板；纸面上传需要照明/背景与笔迹提取诊断。清晰度不足时给出重拍建议。
- 自动字体：本地加载已核验 OFL 的中文书写字体，加载完成再测字形，准确称为字体辅助；旋转/倾斜前计算完整变换包围盒，防止名字被源画布裁断。
- 布局：按墨量档选择真实笔迹，残差驱动不规则分布并做原生尺寸的双向碰撞核查。分离稀疏轮廓与暗部容量问题，保持名字完整和可读。
- 输出：生成后固定模板 / 参数 / 布局快照；PNG 局部无接缝，路径 SVG 必须与实际笔迹吻合。新增完整源图与签名项目包后才叫“可恢复项目”。

墨量诊断、视觉原大检查、真实手写多样性、手机性能与输出合同须全部通过；低平均误差或 8K 尺寸正确均不能代替商业自然笔迹验收。
